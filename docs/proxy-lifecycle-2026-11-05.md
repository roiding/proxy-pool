# 代理临时黑名单、缓存复用与并发预热（2026-11-05）

最新统一渠道/自动补足与表单记录见 `unified-channels-and-console-2026-11-05.md`。

## 用户确认的规则

| 来源 | 验活失败 | 成功下发 | 保存期限 |
| --- | --- | --- | --- |
| 网络列表 | 同一来源临时禁用，清除旧 PASS | 同一来源临时禁用，清除旧 PASS | 每个下载批次 30 分钟后整体清空 |
| 自上传 custom | 删除该连接 | 保留 | 永久，不按缓存/证明计时删除 |

- PASS 只表示“曾在该准确验证范围通过”，**不保证以后一直在线**。
- 网络列表缓存包含未测候选与已通过候选。只有通过同范围检查才可下发，不把下载数当存活数。
- 请求取消/任务总预算结束不是代理失败，不加入黑名单。候选自身探测超时，以及完成的连接/认证/目标/Judge 检查失败，才禁用该网络代理；上传代理则删除其当前来源的库存。供应商读取失败不等于所有代理失效。
- 网络下载行不立即删除，黑名单期间跳过预热、选取和最终下发。同一来源的黑名单不扩散到独立来源或上传库存；品牌展示可以合并，但实际账号、权限与来源 ID 不合并。
- 黑名单默认 30 分钟。管理台「下游项目 → 项目详情 → 网络代理黑名单（秒）」可调整；API 字段为 `network_reuse_cooldown_ms`。0 使用默认值，不是关闭；缩短配置不追溯缩短已生效的窗口。无显式项目时采用默认值。
- 黑名单以稳定 HMAC 连接身份持久保存在 SQLite，不保存原始代理凭据；重启、重新下载、配置版本变更不能绕过同一来源尚未结束的窗口。过期后可重新测活，不复用已清除的旧 PASS；没有永久黑名单。
- 上传的旧本地保留期限不再控制存储；旧提交的到期时间保留为 `uploaded_expires_at` 元数据声明，不当自动删除期限。
- 持久租约、私有 sticky 会话、项目 CD 不等于共享缓存，领取后不删除客户已获得的记录。SCDN 等已启用网络渠道统一缓存和预热；私有会话保留既有安全重验规则。

## 为什么过去会出现“25 次通过，结束时 2/100”

线上旧任务 `warm_fb00795cc6bcfc1a4154addb` 在 18:18:20–18:20:20（北京时间）探测 111 次：通过 25、失败 86。旧实现只有一个后台验活槽，并按最近 30 秒的证明统计 Ready，所以较早 PASS 在任务结束前已被扣除。历史通过次数也不是独立代理库存数。

新实现：授权来源轮询选取、共享有界并发池（四个总探测槽时，三个后台槽、一个留给客户端），按未下发的同范围 PASS 指纹去重凑目标。小缺口也会轮换渠道，不会一直卡在第一个大列表。列表下载最多两个并发，不调用按需供应商囤号。

## 拉取与缓存复用

- 已有当前配置的新鲜缓存时，预热、按需补给及手动刷新均复用该批次；即使所有候选都在黑名单，也不立刻拉取相同列表。
- 同一来源同时到达的抓取合并成一次下载；缺失缓存或下载失败时仍受持久请求间隔、退避和 `Retry-After` 约束，不能靠重启清空限流状态。
- 30 分钟缓存窗口从成功下载/解析结束时计算。窗口到期清候选、证明与 HTTP validators；内存容量驱逐、重启或配置变更也可能使缓存提前消失，但持久黑名单不消失。
- 新 200 下载是新缓存批次，不继承旧 PASS，也不清除黑名单。手动刷新有效缓存不会开启新窗口。

## 交付原子性与失效

- 最终 SQLite 下发事务前持列表缓存独占 fence；租约提交和同来源标黑在同一事务中完成。提交成功后、释放 fence 前清除实际下发代理的旧 PASS。未提交/失败/取消的请求不消费供给、不标为已下发。
- 并发客户端即使配置 shared/max leases > 1，也不能在同来源黑名单窗口内重复领取；同一批中的指纹去重、项目 CD 与池子租约容量仍有效。上传库存不因网络下发而删除。
- 配置/Key 版本、scope/安全 hash、较新失败、权限和 CD 继续复核；不跨目标借用旧 PASS。
- 每秒后台清理到期整批的候选、证明、验证器；读/提交在精确到期点即拒绝，不等待清理 tick。
- HTTP 304 不延长原始缓存窗口；到期后删除验证器并重新完整下载。显式取得新 200 批次是新窗口，不继承旧 PASS。
- 列表仍有既有内存/候选/证明上限。内存供给在进程重启时消失，上传库存持久保留。
- 兼容读取旧 `static_cache_ttl_ms`、来源 `cache_ttl_ms` 与 30 秒 proof 配置；生产列表/上传实际规则由上述生命周期控制。管理系统 API 返回生效 `proxy_lifecycle` 字段。
- 普通列表下发 `validation.valid_until` 为该批次清理时间；上传为 `null`。这是服务端证明/保存规则，不是代理物理到期时间或客户端租约期限。
