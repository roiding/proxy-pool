# 渠道价值准入评估

日期：2026-11-05，Asia/Shanghai。适用仓库：proxy_pool。本表是工程准入裁决，不是本轮实网抓取或公共代理验活报告。

## 1. 口径与结论

一个供应商品牌只计一个渠道。HTTP / SOCKS5、匿名等级、国家、API / HTML 子页是配置选项（variant），不是增加渠道数的理由。同名仓库、镜像、旧域名不另计供给。账号和项目实例仍保持权限、秘密、缓存与交付身份隔离，不能因展示分组而混用。

当前目录提供 **14 个品牌**：12 个公共列表（云代理、积流、齐云、89、LumiProxy、ProxyScrape、OpenProxyList、Geonode、monosans、Spys、Free-Proxy-List、小幻），加已有 SCDN 与 Webshare 已分配列表。**这不等于 14 家已实网可用，更不等于 14 家每天都给免费额度。** 原有品牌的兼容价值也不构成永久资格：部署验收无供给或维护收益不足时，应停用并重新评估。

准入条件：

1. 供给必须是本项目支持的真实 HTTP / SOCKS5 连接，不是内容抓取 API、VPN 或端口开放线索。
2. 已有可理解、可测试的请求/响应契约及明确协议，错误、分页、认证不能靠猜。
3. 有预期边际收益：结构化信息、可复用低成本适配、已有部署兼容，或不同供给路径的合理补充。**未测唯一新增 PASS 时，不声称独立供给。**
4. 维护成本可控：不执行站点 JS，不绕验证码，不依赖不明镜像或自动切地址，不降低 TLS 校验。
5. 不自动注册、购买、换号或消耗不明扣费；账号列表只读已经分配的连接。
6. 值得构建与真实上线分开：真实 fetch/parse 和小样本 Judge/目标 TLS 验收后才能判断部署价值。

缺少证据时采用“不纳入本批次”，不以“先列一个 pending 渠道”扩充管理台。被排除提案只留本文。低层 parser/site ID 作为诊断或既有定义兼容，不是新建渠道的准入凭据。

## 4. 代码落地与执行边界

- `sites/channels.go` 是已准入公共品牌及路径配置的清单，`channel_templates.go` 加 SCDN/Webshare 形成创建目录。
- 管理台每个品牌一行，协议合并；配置选项默认折叠，新建时才选择。实例按品牌分组但真实 `source_id` 不迁移、不删、不合并。
- 新建公共站点来源与旧 upsert API 的新建路径都受准入限制；不能通过手填已排除 `site_id` 创建新来源。变更已有配置也不能转向另一个被排除入口。
- 原 `sites.Catalog`/`ByID`、低层 `/admin/sites`、显式 CLI `-site` 保留诊断/兼容。`-list` 是品牌目录，`-all` 每个已准入公共品牌只查主配置，不再遍历每种协议/筛选。CLI诊断被排除端点不等于把它加入渠道。
- 旧未准入实例不批量删除，允许管理/迁移；停止新建也不清租约/CD。既有非停用端点可保持原行为，由管理员验收后决定停用，不能在本轮未经授权删除生产配置。
- 可创建目录没有商业 pending、停更、退役或 TLS 不兼容占位项；提案原因只留本文。

## 5. 后续保留/退出标准

逐品牌选择一个明确配置，先抓取/解析，再少量唯一候选的 Judge/目标 TLS 验收；不要发送业务 Cookie、登录或个人数据。记录网络出口、TLS、唯一候选/抽样分母、PASS/FAIL、更新时间、错误与限流。

只有实际结果能决定长期价值：新增唯一 PASS、能被项目真正发放的独立连接、时延/成功率、抓取及维护成本、账号读取/提取额度消耗。镜像/协议不重复计品牌，重复代理不重复计收益。长期没有增量有效供给、持续改版或只有不兼容产品的，停止刷新并退出可创建目录，而不是无限保留“可能有用”。本批次没有给收益率或停用阈值填未经测量的数字。
