## 2. 需求契约：来源、业务路由与会话分开

| 概念 | 代表什么 | 管理方式 |
| --- | --- | --- |
| 上游渠道 Source | 一份实际供给配置，例如某个 TXT 订阅或某个供应商账户 | 管理页创建、回读、编辑、停启、测试、查看历史 |
| 适配器 Adapter | 代码提供的解析与协议能力，例如 `scdn_v1` | 系统展示能力和版本；不是让管理员编辑 Go 代码 |
| 静态库存 Inventory | 上传或 URL 同步得到、允许以后再次挑选的代理候选 | 入池、验活、冷却、到期、退役 |
| 下游应用 Consumer | 调用本服务的业务身份，可持有多个密钥 | 授权渠道、配额、CD、密钥轮换、查看自己的任务和租约 |
| 业务路由 RoutePolicy | 某种业务允许使用的源和分配行为，类似 Resin 的 Platform | 配置粘性/轮换、过滤、故障策略和使用上限，不代替认证 |
| 会话绑定 SessionBinding | 某应用、路由和业务会话对应的固定连接/出口绑定 | 创建、命中、同出口恢复、显式重绑、释放和到期 |

“渠道”默认指上游供给渠道；对下游统一称“应用/调用方”，不再两个地方都叫渠道。每个下游应用的 CD 独立，换 Key 不等于换业务身份。

“供应商 API 来源”与“下游 API 业务”是不同维度。静态库存和 API 按需来源都可以服务粘性或轮换业务；推荐提供 `api-sticky` 和 `crawler-rotate` 两个路由模板，不把粘性写成所有 API 来源固有的全局开关。

### 2.1 必须成立的规则

1. **API 来源不进入可重复分配的静态库存。** 只在下游需要新分配时拉取，未使用条目随请求结束丢弃；已建立的粘性绑定可在自己的会话期限内复用，不重复取号。
2. **不入池不等于完全不落库。** API 代理仍需保存指纹、预约、租约/交付、会话私有连接快照、CD 和审计证据；这些记录不能被库存选择器或其他会话当作候选。
3. 静态上传和静态 URL 进入同一库存导入管线；下载成功不等于验活成功。
4. 保留当前“每次交付属于本次请求的验活”契约。API 代理在本次获取时做交付前验活，不先入池验活再重复验证；静态预热只是提高后续取号命中率。
5. 渠道选择先看配置和运行状态，不能等整个池子耗尽才考虑切换到其他来源。
6. 预热的目标是指定范围内“当前近期验活通过且有分配资格”的静态代理数量，不是本轮探测次数或历史成功数。
7. 业务 CD 限制新分配，同一活动粘性绑定可复用自己的分配；代理失败冷却、源熔断和抓取频控仍独立校验，粘性不能绕过权限和硬故障。
8. 状态存储不可靠时拒绝交付，不能忽略 CD/租约写入失败后继续返回。
9. 本服务只分配代理连接信息，不转发下游业务流量，也不能真正阻止客户端在租约过期后继续使用已经拿到的代理。
10. 非粘性不等于必换 IP。爬虫模板明确按近期出口去重及连续排除规则执行，无新出口时说明耗尽，不能把随机重复包装成成功轮换。
11. 固定代理连接不必然固定出口。严格粘性或严格出口轮换需要相应上游能力，普通轮换网关不能只靠本地绑定提供该保证。

### 2.2 暂不做的事

- 不拆微服务，不引入 Redis、消息队列或额外数据库服务。
- 不提供运行任意下载脚本、上传 Go 插件或执行 JavaScript 的管理功能。
- 不把未知协议猜成 HTTP，不承诺轮换网关下一条连接仍使用验活时的出口。
- 不为了预热库存而自动调用付费 API，不默认增加后台供应商取号。
- 不通过“跳过验活”“忽略新分配 CD”或伪造会话命中来凑够数量。
- 不在没有真实样本时实现一个能配置所有供应商的通用解析平台。

## 3. 管理端：从功能表单堆叠改为实体与任务管理

### 3.1 页面结构

| 页面 | 主问题 | 内容和主要操作 |
| --- | --- | --- |
| 概览 | 现在能否服务？为什么取不到？ | 静态库存概况、近期验活、在线取号成功率、熔断源、进行中任务、错误告警 |
| 渠道管理 | 供给来自哪里、配置是什么？ | 所有渠道统一列表；新建、详情、编辑、停启、显式测试、同步/验活、运行记录 |
| 静态库存 | 池里实际有什么？ | 按来源、协议、地区、健康、到期筛选；脱敏连接、最后观察、冷却原因、退役和明确恢复 |
| 任务中心 | 操作执行到哪一步？ | URL 同步、导入、预热、全量验活、API 诊断；进度、结果、取消、重试、历史 |
| 下游应用 | 谁能调用、采用什么业务路由？ | 应用、密钥、授权、路由策略、CD、活动粘性会话和可选预热权限 |
| 调用记录 | 本次为什么成功或失败？ | 请求链路、换源原因、各阶段耗时、缺口分类、交付与反馈记录 |
| 系统设置 | 系统策略与安全边界是什么？ | 默认策略、探测目标、GeoIP 状态、管理登录设置、部署版本和诊断 |

不是把现在两个创建卡片和一张健康表简单塞进同一个大卡片。渠道列表是主视图，创建和编辑放在抽屉或独立详情页；预热、密钥和全局统计不占据渠道配置区。

### 3.2 渠道统一列表

展示：名称/ID、类型、适配器、启停、优先级、运行状态、最近操作、下一次允许调用/同步时间、操作入口。

类型使用业务名称：

- 静态上传：手工粘贴或上传文件。
- 静态订阅：配置 URL，服务器主动下载。
- API 按需：下游请求触发供应商获取，不入池。

静态渠道展示候选数、近期验活数、过期/冷却数。API 渠道展示最近窗口的调用次数、实际返回数、验活通过率和交付量，**不显示一个虚构的“API 库存数”**。

共同操作是“详情 / 编辑 / 启停”。类型特有操作由能力决定：

| 类型 | 特有操作 | 不应出现 |
| --- | --- | --- |
| 静态上传 | 导入、验活、查看库存 | 定时下载、供应商取号 |
| 静态订阅 | 立即同步、查看同步记录、验活、查看库存 | 把下载数直接叫作活跃数 |
| API 按需 | 测试配置、少量诊断取号、查看交付记录 | 入池、池库存预热、定期全量验活 |

所有网络或配额消耗操作都单独触发。“保存配置”不偷偷取号；诊断显示样本数、可能消耗的配额和结果是否进入正式统计。

### 3.3 渠道编辑字段

共同字段：显示名称、不可变 ID、类型、适配器 ID、启停、优先级、超时、并发、源级运行策略、备注和配置版本。

静态上传：默认代理协议、本地保留策略、容量策略、退役规则；导入内容属于独立操作，不把一次文件上传当作重新创建整个渠道。

静态订阅增加：下载 URL、必要的认证引用、刷新间隔、导入模式、超时和体积限制、上次同步、下次同步、ETag/Last-Modified、失败退避。

API 按需：供应商选择、该适配器支持的请求参数、抓取批量上限、频控、必要的凭证、预算和供应质量策略。`scdn_v1` 当前已实现的参数是协议、国家代码、数量和最小调用间隔，页面必须可以回读、修改和保存，而不是只有“创建”按钮。

代码决定支持什么协议和响应格式；管理员决定渠道实例使用什么参数。端点默认使用适配器的官方地址，只有适配器明确允许的 base URL/镜像配置才可覆盖。不展示一个实际上不会生效的 URL 或 JSON 字段。以后确有其他简单 API 需求时，增加受限的声明式 HTTP 适配器，不改调度器、不执行自定义脚本。

渠道另展示上游能力：端点稳定性依据、是否支持供应商 session token、已知有效期/粘性上限。粘性与轮换开关放在下游应用的“业务路由”中，而不是一个源只能供一种业务。当前 SCDN 没有供应商级固定出口/会话 TTL 依据，必须显示为未知或观察级保持。

下游应用增加“活动会话”子页，展示绑定出口、代理、来源、保证级别、到期、最后取号、命中和重绑原因；提供受权限和版本保护的释放/重绑，不与上游渠道编辑混为一谈。

### 3.4 配置的生命周期

- `POST` 只创建；ID 重复返回冲突，不覆盖旧源。
- `GET` 返回可编辑配置、能力和脱敏凭证状态。
- `PATCH + expected_version/If-Match` 更新；旧版本表单返回 409，避免互相覆盖。
- 导入、下载、验活、启停、删除是独立命令；一次导入不重置并发、保留时长或启停状态。
- 渠道类型和适配器不能靠普通编辑悄悄互换；需要显式迁移或创建新源。
- 停用立即阻止新任务和新交付；对已发租约默认保留历史、允许释放。需要强制逻辑撤销时单独确认，并说明无法收回客户端已获得的连接信息。
- 删除先显示影响范围，只移除该源的供给关系，不误删其他源共享的静态资源；活动租约、业务 CD 和审计证据按保留规则处理。

### 3.5 交互与视觉要求

保留现有深色、绿色强调的工具界面语境，但重做导航和信息层级。中文说明与等宽的 IP/ID 分开排版，状态必须同时有文字和颜色。

表单要有字段级错误、保存状态和未保存提示；后台操作显示任务 ID、完成数、总量/目标及停止原因。取号失败不能只显示原始 JSON。刷新失败显示“数据已过期”和最后更新时间，不能吞掉错误后继续呈现一张看似正常的旧表。

登录用密码输入框。危险操作有影响说明和确认；密钥仅创建时展示一次，可复制但不写入本地存储。移动端按至少 360px 宽度验收，表格在局部滚动或转为条目卡片，不能把整页撑出屏幕；编辑抽屉和确认弹窗支持键盘操作。

### 3.6 前端实现边界

继续由 Go 内嵌发布静态管理站点，不增加生产 Node 服务。把目前单文件中的页面、样式和脚本拆成页面模块、公共 API 客户端、表单/表格组件和状态展示；优先使用原生 ES modules，暂不为这套规模引入大型前端框架。

页面路由与任务状态可以独立刷新；请求层统一处理鉴权、版本冲突、字段错误、取消与数据过期。适配器字段由明确的能力描述驱动，但所有校验和调度决策仍以服务端为准，不能只隐藏按钮而不检查权限。前端不计算权威的 CD 到期或预热达标状态。

静态资源以构建版本标识管理缓存，页面和敏感 API 禁止缓存；脚本外置便于配置 CSP。交付包括组件/请求层测试与浏览器端到端测试，不把 `node --check` 当作完整页面验收。

## 4. 服务端架构：一个进程、两条供给路径

```text
管理页 / 管理 API
    -> 渠道配置、下游应用、策略、任务

静态上传 / 静态 URL -> 解析、标准化、去重 -> 静态库存

下游 API -> 鉴权、限额、授权业务路由、模式
              |
              +-> sticky 命中 -> 已有会话私有绑定
              |
              +-> 新分配 -> 源调度
                            +-> 静态库存候选
                            +-> API 适配器 -> 本请求临时候选

上述候选或绑定 -> 当前资格、指纹、预约或已有容量所有权
              -> 本请求验活、出口与地区
              -> 交付事务：租约、绑定、CD、审计
              -> 返回连接信息
```

复用解析、代理连接、验活、指纹和交付规则；不复用“必须先写库存才能取号”的入口。粘性命中先走自己的绑定，不重新执行供应商取号或申请额外容量；新建粘性与轮换再进入选源调度。

建议在现有模块化单体上演进：

| 模块 | 职责 | 禁止越界 |
| --- | --- | --- |
| SourceService | 渠道 CRUD、版本、启停、能力检查 | 不进行隐式供应商取号 |
| AdapterRegistry | 适配器元数据、参数校验、供应商响应标准化 | 不直接修改库存、租约或 CD |
| StaticSyncService | 下载/上传、解析、批次、库存更新 | 不把下载成功认作代理可用 |
| RoutingPolicyService | 业务路由授权、模式、过滤和连续性要求 | 不把策略名作为认证凭证，不静默放宽能力 |
| SessionService | 粘性绑定、TTL、版本、同出口恢复、显式重绑 | 不把私有 API 绑定放进公共库存，不忽略硬故障 |
| AcquireScheduler | 请求预算、选源、换源、候选调度 | 不忽略权限和 CD，不无限重试 |
| ValidationExecutor | 有界探测、失败分类、证据和出口观察 | 不自行决定全局永久封禁 |
| DeliveryService | 预约、最终检查、租约、业务 CD、结果状态 | 不绕过存储错误交付 |
| JobService | 预热、验活、同步和诊断任务的状态及恢复 | 不形成无界队列 |
| ConsumerService | 应用身份、密钥、授权、配额 | 不把 Key 当成可随意重建的业务身份 |
| Maintenance | 到期、回收、统计聚合、历史清理 | 不擅自发起 API 取号或全池探测 |

## 5. 静态 URL 渠道：下载是同步任务，不是简单定时 curl

### 5.1 最小可用契约

- 支持管理员配置绝对 HTTP/HTTPS URL，推荐 HTTPS；默认只允许 GET。
- 默认手动同步；配置正数间隔才自动同步。UI 单位为分钟，内部统一毫秒，初始建议 1 分钟至 7 天。
- 初始下载超时建议 15 秒、解压后正文上限 8 MiB，并另设行数和单行长度上限；数值是起始限制，不是性能保证。
- 只允许一个源同时运行一个同步任务；全局下载并发初始为 2。
- 同步进度与结果持久化：HTTP 状态、耗时、字节数、总行数、新增、更新、重复、拒绝、被封禁跳过数。
- `next_run_at`、最近成功和失败退避保存在 SQLite，重启不会让所有源同时立即抓取。补跑最多一次，加抖动，不补发所有错过的周期。
- 支持 ETag 和 Last-Modified，304 只表示列表未变，不表示代理验活通过；来源存续时间和健康新鲜度必须分开。

### 5.2 同步安全

使用专用 HTTP Client，明确代理环境变量策略、连接池、TLS、响应头、重定向和正文上限。URL 初次解析、每次重定向及实际 DNS 解析后的拨号均检查地址范围，拒绝环回、私网、链路本地、云元数据等目标，规范化 IPv4-mapped IPv6；不只在保存 URL 时检查一次。

确需内网订阅时使用管理员单独配置的允许域名/IP 范围，不能通过订阅内容或下游参数放宽全局网络策略。默认不跨域转发认证头、不跟随 HTTPS 降级，不允许 `file:`、本地路径或执行脚本。凭证、含 Token 的查询参数、失败解析样本都要脱敏，错误文本也不能泄漏原始代理密码。

### 5.3 导入与错误语义

默认 `append`：新增或更新，不因某条数据在新文件中消失就删除旧供给。相同连接稳定去重，保留失败历史、手动禁用和退役记录；只改变列表顺序不能复活被淘汰的代理。

第一阶段只交付追加导入。需要 `snapshot` 时作为显式能力增加：先完整下载、解析和差异检查，只有完整可信快照才能撤销缺失的源供给；空列表、异常大规模删除、截断和格式异常不得自动清池。

下载失败保留旧库存，进入“同步失败/下次重试”状态，不把所有旧代理判死。403/429/5xx 分别处理，尊重 Retry-After。先写有界暂存批次、分块标准化，再发布有效结果；避免一个大列表长期占用唯一 SQLite 连接。ETag 仅在对应批次成功处理后确认。

本地保留期限代表库存策略，不是假装供应商承诺代理存活这么久。上游真实到期、来源最近出现时间、库存保留时间、验活时间分别保存。

## 6. API 按需渠道：不入池，但交付仍然可靠

以下是“需要新分配”的路径，包括轮换和首次建立粘性绑定。同一活动会话命中时直接验活其私有绑定，不重新拉供应商接口。

1. 下游请求经过身份、权限、数量、CD 和预算检查。
2. 调度器选中某个允许的 API 渠道，获取源/账户调用许可。
3. 根据所缺数量和批量上限调用适配器；响应转换成本请求的临时候选。
4. 先做连接指纹去重、业务 CD、负面缓存和生命周期检查，尽量不对明显不可返回的条目浪费验活。
5. 预约候选，执行本次请求的验活；本次出口国家不满足过滤条件时不交付，但不把代理记为故障。
6. 通过后进入统一交付事务。租约/交付快照、CD 及需要的会话私有绑定可以落库，静态库存表不增加行。
7. 失败、重复、CD 命中或供应不足时，在本请求预算及连续性规则内换条目或换源；请求结束丢弃未分配条目，已绑定连接只供该会话使用到期。

API 新分配返回相同代理也不能绕过 CD；另一 API 源或静态源给出相同连接时，同一下游应用仍受同一指纹窗口约束。活动粘性绑定的合法命中属于复用已有分配，按第 9 节处理，而非新分配。

并发获取默认采用“按源/账户串行许可 + 有界等待或换源”，不把当前简单的 busy=409 误称为完整的 singleflight。只有适配器声明调用免费、幂等且过滤范围一致时，才考虑合并已入场请求的供应商调用；合并也不能共享旧验活证据或生成后台可复用库存。

诊断取号是明确的管理员例外动作：少量、有预算、结果有记录、退出即丢弃，不变相成为“先拉一批存起来”。付费或购买型接口没有明确预算及超时幂等契约前不启用自动重试。

## 7. 动态调度：规则可解释，失败能够及时换源

### 7.1 四种 CD 与一种租约

| 名称 | 作用范围 | 触发点 | 作用 |
| --- | --- | --- | --- |
| 业务新分配 CD | 下游应用 + 连接指纹/出口去重键 | 新分配进入交付边界 | 阻止近期重复新分配；活动粘性绑定只可复用自己的分配 |
| 代理失败冷却 | 连接指纹 + 验活配置版本 | 归因明确的代理失败 | 避免连续浪费探测 |
| 源供给熔断 | 上游源 + 供给质量 | 连续独立候选失败/低收益 | 库存仍有也先换源 |
| 抓取频控/抓取熔断 | 上游源或共享供应商账户 | 调用间隔、429、超时、额度 | 控制上游调用，不能与库存质量混淆 |
| 租约/预约 | 连接指纹 + 容量槽位 | 分配或探测期间 | 控制本服务内的并发占用，不等同于 CD |

源拉取失败不必阻止已有静态库存取号。某个 Judge 故障也不是源或所有代理故障：验活目标另有运行状态，故障时切换到明确批准的兼容探测目标，或返回基础设施不可用。

### 7.2 推荐的源选择规则

先做硬过滤：应用授权、源启用、协议/能力、国家能力、预算、时间、熔断状态。再按管理员配置的优先级选择；同优先级考虑近期验证收益、延迟、失败比例和公平轮转。历史数据只用于排序，不能授权直接下发。

默认策略可以是“静态优先、API 兜底”，但这是可配置路由，不是写死在 `inventory empty` 分支中的唯一策略。也支持 API 优先和同优先级轮询。

开始不需要机器学习或不可解释的大评分公式。先实现明确预算、确定性故障切换、滑动窗口/衰减统计和结构化决策日志，积累数据后再调权重。

### 7.3 单次请求算法

```text
admit -> 检查业务路由、模式与会话；合法绑定命中走复用验证
新分配 -> 确定请求截止时间和可用源
  -> 取得源许可
  -> 获得少量静态/临时候选
  -> 检查本请求去重、CD、健康、剩余预算
  -> 预约 -> 探测 -> 校验本次观察和资格
  -> 够数量：停止继续生产候选，收敛在途工作，最终提交
  -> 此源失败到阈值：本请求立即换源，必要时打开持久熔断
  -> 所有源暂不可用/预算耗尽：返回部分结果或明确缺口
```

所有计数在实际开始动作前原子领取；分页大小不决定尝试数。调度器接收工作结果再决定下一批，不能提前把一个坏源的整页塞满请求队列。

建议起始限制：全局探测 4 个、每请求最多 2 个、在线取号最多 8 个；每源本请求连续失败 3 条独立候选即换源；单请求总尝试沿用 `min(5*count, 25)` 的量级，但真正按动作硬限制；API 总调用预算建议 2 次，随后依据收益调整。所有限制和排队时间均受请求截止时间约束。

源质量熔断建议起点为连续 3 次明确代理失败，30 秒起步，指数退避至 15 分钟并加抖动。这些是初始策略，不是测量后的 SLO。单个重复坏代理不能反复贡献多个独立源故障样本，CD 命中和地区不匹配也不算代理失败。

### 7.4 真正的半开状态

`CLOSED -> OPEN -> HALF_OPEN -> CLOSED/OPEN` 要有持久状态和短期试探许可。到期不代表所有请求一起恢复；一个源只放行一个恢复试探，失败重新退避，成功逐步恢复。许可有 owner、generation 和超时，旧探测结果不能关闭后来重新打开的熔断。

已经缓存的候选在探测前仍需检查源状态。供应商调用超时或配额故障使用独立抓取熔断，不能清零代理健康或误清静态库存。

### 7.5 失败结果必须解释清楚

至少区分：库存为空、过滤不匹配、业务 CD 排除、容量占用、源熔断、供应商限流、配额耗尽、上游异常、验活基础设施异常、无候选验活成功、请求预算耗尽、存储不可用。

返回 `request_id`、requested/delivered/missing、稳定错误码、可计算时的 `retry_after_ms`。部分交付必须由调用方显式允许。管理员记录包含选过的源和换源原因，普通下游响应不能泄漏供应商凭证或内部配置。

## 8. 预热与手动验活：目标、范围和停止条件都要确定

### 8.1 预热目标定义

`ready_now` 是指定范围内去重后的静态代理数，同时满足：

- 源启用、资源未禁用、供给在有效期内，有足够的最低使用窗口。
- 当前验活配置下最近一次有效证据为成功，且不超过 `freshness_seconds`。
- 没有更新的明确失败、代理失败冷却或阻止分配的源状态。
- 有可分配容量；若任务属于某个下游应用，还必须符合该应用授权和现有 CD。
- 需要国家过滤时，有符合要求的观察；未知地区可以被探测以完成冷启动。

默认新鲜度可先取 120 秒，实际按业务启动窗口配置。请求要的是“当前达到 N”，不是“本轮再测出 N 个”。开始时已有 80 条合格、目标 100，就主要补齐缺少的 20 条。

### 8.2 任务执行

创建任务返回 202 和稳定 `job_id`，浏览器刷新、服务重启都能查到。先计算 `initial_ready`，逐批探测，持续更新 `ready_now`；资源被占用、过期或失败时不再计入。完成前重新计算达标数量，不能仅凭本轮 PASS 累计结束。

分别保存 `initial_ready`、`ready_now`、`newly_validated`、`probed`、`failed`、`inconclusive`、`skipped_cd` 和 `retired`。允许有限在途探测导致轻微超额，但不能无限超出尝试预算。

停止原因：`target_met`、`inventory_exhausted`、`sources_cooling`、`deadline`、`attempt_limit`、`cancelled`、`storage_error`、`validation_infra_unavailable`。未达标是明确的不足结果，不显示绿色“全部完成”。

API 按需源不计入预热库存、不被预热获取。静态 URL 同步可作为显式前置任务，任务说明中要写明“先同步再预热”，不能隐式增加外部操作。

目标式预热、全量静态验活、定时静态验活使用统一任务框架和探测执行器。任务有源范围、截止时间、尝试上限、配置版本、取消信号、心跳和恢复检查点。采用有界分页/任务游标，避免随着库存规模不断扩大 `NOT IN` 列表和内存集合。

### 8.3 在线优先

全局仍使用少量共享探测槽位，但在线请求优先；建议后台任务最多占用 1 个保底槽，空闲时再借用额外槽位。在线请求到达后停止继续派发低优先级任务，已经开始的探测按很短的超时收敛。

夜间验活也要取得统一探测预约，不能只在第一次 SELECT 时排除租约、随后不加保护地探测。避免“预热、夜间、正式取号”同时检查同一连接。

预热只保证任务完成时的估计可用数量，不能保证若干分钟后资源仍存活或不被其他业务消耗。若以后要求为某业务独占保留 N 条，那是单独的预留产品能力，不偷偷混在预热里。

## 9. 业务 CD、下游应用与交付一致性

### 9.1 推荐采用固定窗口，而非查询时回看窗口

本规划建议：本次请求的 `cd` 覆盖应用默认值，用于**本次新分配产生的窗口**；不能缩短同一代理已经生效的旧窗口。同一活动粘性绑定命中是复用已有分配，可使用自己的窗口，不是开一个新租约。

例：应用 A 在 10:00 新分配 P，`cd=300`。10:01 即使改传 `cd=0`，另一个会话或 rotate 请求仍不能新分配 P；到 10:05 后才有资格。原活动粘性会话可以在有效期内复用自己的 P。应用 B 不受 A 的业务 CD 影响，但仍受全局容量、代理健康等限制。

有效 CD 有最大值；是否允许低于应用最小 CD 是应用策略。`cd=0` 只表示新分配不建立额外窗口，不是越过旧窗口或租约。释放租约、换源、重新下载、轮换 Key 都不能重置已经生效的 CD。合法会话命中不额外延长 CD 或绑定 TTL；如要“会话结束后再冷却”，另设明确策略。

这一点与当前实现和测试的“显式 0 禁用旧窗口”不同，属于需要明确确认的行为变更；实施前要固定契约并更新调用示例，不能静默改义。

### 9.2 代理身份

基础业务去重键是规范化连接指纹：协议、主机/IP、端口、凭证版本、真实上游会话上下文。不要把上游 source_id 或任意业务 session_key 加进这个键，否则换源/改会话名就能绕过 CD；也不要把出口 IP 等同于稳定连接身份。

爬虫模板优先提供 `dedupe_by=exit_ip`，在验活后增加原子出口去重；不同端口同出口不能充当多个新 IP。`cd=0` 不等于必换 IP，要求连续必换时仍排除上次出口，无新出口明确返回耗尽。轮换网关若不能绑定下游连接与观察出口，就不能声称提供实际业务级严格出口去重。

### 9.3 原子交付边界

新分配预约阶段占有短期的消费者/代理许可；探测不持有数据库事务。最终短事务检查源版本、资源/凭证资格、故障 epoch、期限、证据、容量、应用授权以及 `cooldown_until`，再一并落租约、会话绑定、交付状态和 CD。粘性命中验证绑定 owner/generation 及已有容量所有权，不增加一个会被自身占用挡住的新槽位。

CD 时间用统一整数毫秒保存和比较。已有窗口只允许显式延长，不能被小参数覆盖成更早时间。必要写入失败则回滚，不返回代理。

数据库事务与 HTTP Socket 无法真正原子提交。“客户端确实收到了”不是服务能可靠判定的事实：定义持久化的 dispatch 边界，一旦开始发送或发送结果不明，保守保留租约和 CD。明确未发送的失败批次才可按操作 ID 回滚。文案使用“已提交交付/发送结果不明”，不伪称 exactly-once。

幂等重试保留同一操作和容量，不重复购买或延长 CD。沿用严格验活时，重试回放也必须满足证据新鲜度；过期证据需重新验活已有租约上下文，不能无限返回缓存的旧成功响应。

### 9.4 权限与密钥

- 下游应用可有多个 Key；CD 和配额属于应用，Key 只是认证凭证。
- 默认只允许取号及操作自己的租约；访问其他应用租约返回 403 或不泄漏存在性的 404。
- 预热可按 `inventory:prewarm` 单独授权，只在应用允许的静态源、数量和预算内创建任务；业务自动化无需拿管理员 Token。
- 管理密码、管理 API 凭证、下游 Key、身份指纹密钥与凭证加密密钥分清职责。管理密码修改不改变代理 ID、CD 或下游业务身份。
- Key 仅返回一次随机明文，服务保存哈希；支持启停、到期和保留 consumer_id 的平滑轮换。
- 保留链接携带 Key 的兼容需求时明确泄漏风险，禁止在日志、Referer、异常和复制示例中带出真实 Key；默认推荐请求头。
- 管理设置不显示完整现有密码/Token；改密需重新认证和明确确认。当前所有密钥保持不变，不擅自给用户密码加后缀或自动轮换。

失败反馈先保存为消费者观察，按租约归属、反馈 ID 和窗口校验；目标站点 403/429 不等于代理死亡。重复报告不能重复累加健康失败；必要时触发服务自己的有限复核，而不是让一个下游通过反馈清空共享库存。

### 9.5 粘性与轮换是一等路由模式

采用显式 `mode=sticky|rotate`，由授权业务路由设默认值，限制请求是否可覆盖。sticky 缺会话键返回错误，不能学一个“忘带账号就随机换 IP”的宽松回退。绑定键为 consumer + route + session_key_hash；不同消费者隔离，Key 轮换不改变绑定。

sticky 第一版每次获取一个会话绑定，采用固定 TTL，与其容量租约期限对齐，并受已知上游有效期和能力上限约束。命中同一绑定仍执行本次取号的验活；同出口替代不延长 TTL。到期返回明确状态，按预先设定的到期策略或显式重建处理。

API 粘性模板默认 `same_exit_or_fail`：原连接失效后可以在授权范围内寻找合格的同出口节点，找不到就报会话不可用，而不是偷偷换 IP。允许 `rebind` 的业务可以换出口，但必须返回 changed、原因和新 generation。上游能力不足时不能宣称严格固定出口。

rotate 不维护粘性绑定，按配置执行连接/出口窗口去重、批内去重和并发原子领取；耗尽时明确不足，不把随机重复当轮换成功。会话释放、新建另一个会话或强制重绑都不能借“粘性例外”绕过新分配 CD。

Resin 值得借鉴的是业务策略/账号分层、出口锚点、同出口替代、P2C 和配置版本保护；不能照搬的是随机即轮换的假设、同出口失败后自动换出口、租约弱持久化，以及信任可路由集合后不再做本项目要求的交付验证。

本项目仍以取号 API 为边界，不自动成为转发网关。爬虫需要每个业务请求换出口，就要配合重新取号/更换连接；同一 CONNECT/SOCKS5 长连接不能在内部无损逐请求换 IP。完整接口示例、私有绑定生命周期和测试要求见 `/Users/roiding/Documents/ChatGPT/proxy_pool/docs/resin-routing-study.md`。

## 10. 验活、出口 IP、地区和流量

### 10.1 验活不一定打本服务

提供明确注册的 ProbeProfile：

| 方式 | 优点 | 约束 |
| --- | --- | --- |
| 自建签名 Judge + 本地 GeoIP | 可控、签名校验、无第三方地理查询配额；复用当前实现 | Judge 自身有出站响应流量；反代真实 IP 信任链必须正确 |
| 经候选代理访问第三方 HTTPS IP/地区服务 | 可以一次取得本次出口和地区，避免自建 Judge 的响应流量 | 受服务条款、TLS、限流、故障和数据格式影响 |

使用第三方时，请求必须确实经候选代理发出，获取该连接的出口；不能本机直连后查供应商给出的主机 IP，再当作代理已验活。严禁探测失败后直连兜底，并把直连结果算作 PASS。

“ip-api 的 45 次/分钟不是整套代理服务共享 45 次”这一点是对的：官方限制按调用来源 IP 计数，代理访问时通常是出口 IP。多个代理可能共享出口，重复预热/取号也可能累积请求，因此按可观察出口和响应头处理限流，不能反过来假设没有任何限制。

本轮核对 [ip-api JSON 官方文档](https://ip-api.com/docs/api:json)：免费入口为每来源 IP 45 次/分钟；需处理 `X-Rl` / `X-Ttl`；免费版本不提供 HTTPS，且不允许商业使用。对不可信公共代理，用未加密且无签名的免费响应不能提供与已验证 TLS/签名相同的信任。因此第三方方式可以做，但生产配置要选择满足业务条款和安全要求的接口，不能默认直接用免费 HTTP 替换现有签名 Judge。

地区是带时间、数据来源和数据库版本的观察，不是承诺；保存 `observed_exit_ip`、country/region/city、`observed_at`、profile、GeoIP 版本。供应商声明与实际观察分栏。需要地区硬过滤时，本次观察无法确定地区就返回不足或明确的定位不可用，不能放宽要求悄悄下发。

### 10.2 流量结论的边界

不能笼统说“服务器只计算上行”。应明确是应用监控流量、网卡流量、套餐扣减还是超额计费；不同产品、地域、共享带宽和 CDN 路径可能不同。若实例合同按公网出方向计费，则入方向不扣该出网额度，但不是入方向完全不存在流量。

本轮没有访问云账号账单；华为云公开文档请求返回了安全验证页，因此不把具体实例的扣费方向写成已核验事实。上线前按该实例实际套餐确认出网/入网、免费额度、超额单价、统计口径及告警。

第三方 Judge 只能节省自建 Judge 响应这一部分，本机到代理的请求、TCP/TLS 握手和管理/取号响应仍有流量。流量估算应以同一时段公网出方向测量为准，不继续沿用未经测量的“每万次只需若干 MB”承诺。真正应优先优化的是不必要的抓取、重复探测、故障循环和公开接口滥用。

## 11. 存储与 API 设计

### 11.1 为什么现在不需要 Redis

单实例、一个 Go 进程、少量有界探测，SQLite WAL 足够作为渠道、任务、租约、预算和 CD 的统一事务权威。Redis 并不能修复缺少归属校验、错误的状态机或被忽略的写入错误，反而带来双写一致性和额外内存维护成本。

网络请求不占用数据库事务；写操作短且有界，列表分页，历史清理分批。优先观测 SQLite 等待、事务耗时、队列时间、磁盘和 RSS。网络验活等待通常比存储更早成为瓶颈，但必须用本机实际负载验证，不能据此承诺 QPS。

只有单机瓶颈经测量确认、或确实需要多实例时，再评估 PostgreSQL；Redis 可做派生缓存/限流，不成为与关系库冲突的另一份租约和 CD 真相。SQLite 文件不放网络共享盘，也不让多个独立进程靠各自内存锁共同服务。

### 11.2 数据模型演进

| 实体/表 | 变化 |
| --- | --- |
| sources | 增加业务类型、adapter_id、名称、可版本化配置和路由/运行策略 |
| source_circuits / runtime | 区分抓取和供给状态；持久频控、额度、半开许可、next_run_at、最近错误 |
| proxy_resources / source_offers | 限定为静态库存；保留多源供给关系和退役约束 |
| reservations / leases | 使用统一连接指纹；增加 source_id、配置版本、consumer_id、操作 ID；静态资源外键可选 |
| consumer_proxy_cooldowns / usage | 按 consumer + 去重键类型 + 指纹/出口保存 cooldown_until 与必要的绑定 owner，不依赖库存外键 |
| consumers / api_keys | 应用与密钥分离；授权、默认 CD、限额属于应用 |
| route_policies / session_bindings | 业务模式、会话键哈希、owner/generation、固定期限、anchor、源版本和关联容量租约；绑定强持久化 |
| jobs / job_events | 有界持久任务、源范围、状态、进度、截止、游标、取消和错误 |
| validation_attempts / observations | 统一结果枚举、实际 source_id、运行上下文、完成时间、失败归因和地区来源 |
| audit_events / operation records | 配置变更、敏感操作、交付与重试状态；不保存无界原始响应 |

未分配 API 候选只在本次请求内存中；已交付的短期租约及粘性会话私有连接快照加密存储，终态不得回池。不能为了沿用旧外键又把它偷偷插入 `proxy_resources`。对静态与 API 相同连接，指纹必须相同，交付容量和业务 CD 因而能够统一。

观察记录也要与静态资源强外键解耦，按指纹和证据保留规则管理；保存 API 观察不生成可被库存选择器发现的资源行。公开响应的连接字段保持兼容，不暴露加密材料或供应商账户凭证。

优先复用已有表和服务，不一次性新增庞大平台。可先用少量明确类型字段及版本化 JSON 保存复杂配置；高频筛选、时间和唯一约束使用有索引的类型化列。

建议详细任务/调用日志保留 7 天、脱敏管理审计 30 天、汇总统计更长；这是待容量验证的初值。活动租约、未决交付、有效 CD 和明确封禁不能被普通日志清理删除。终态预约和租约需要真正清理，避免只有 state 改为 EXPIRED、表却永久增长。

### 11.3 建议 API 表面

以下为目标接口，不表示当前已经提供：

| 接口 | 用途 |
| --- | --- |
| `GET /v1/admin/adapters` | 已安装适配器、版本、能力和可配置字段 |
| `GET/POST /v1/admin/sources` | 渠道列表、创建 |
| `GET/PATCH/DELETE /v1/admin/sources/{id}` | 配置详情、版本化修改、删除 |
| `POST /v1/admin/sources/{id}/sync` | 静态 URL 同步任务 |
| `POST /v1/admin/sources/{id}/imports` | 静态导入任务 |
| `POST /v1/admin/sources/{id}/diagnose` | 有界 API/配置诊断，不入池 |
| `POST /v1/admin/sources/{id}/validate` | 静态源验活任务 |
| `POST /v1/prewarm` | 管理员或授权应用发起目标预热 |
| `GET /v1/jobs/{id}`、`POST /v1/jobs/{id}/cancel` | 按归属和权限访问任务 |
| `GET /v1/admin/inventory` | 分页查询静态库存 |
| `/v1/admin/consumers`、消费者下的 `/keys` | 应用、授权与密钥管理 |
| `/v1/admin/routes`、`GET /v1/sessions/{id}` | 业务路由策略，以及按对象归属保护的会话状态 |
| `POST /v1/sessions/{id}/release`、`/rebind` | 显式结束/重绑会话，校验 generation 与幂等键，不清空业务 CD |
| `POST /v1/proxies/acquire` | 保持现有下游主入口，扩展明确的路由与错误语义 |
| `POST /v1/leases/{id}/release`、`/feedback` | 仅本人或管理员能操作，反馈幂等 |
| `GET /v1/admin/operations`、`/system` | 调用审计、运行和构建版本 |

老管理接口通过受权限保护的兼容层过渡，新页面只调用新契约。下游已有 connection/validation/source_id 字段尽量保留；代理指纹仍可通过旧 `resource_id` 字段兼容暴露，但不再暗示其一定属于静态库存。

建议预热请求示例：

```json
{
  "count": 100,
  "filters": {"source_ids": ["static-main"], "transports": ["http"]},
  "freshness_seconds": 120,
  "deadline_ms": 120000,
  "max_attempts": 500
}
```

consumer 身份由认证确定；不能让下游任意填写其他 consumer_id。POST 使用幂等键避免重复点击启动多份任务；同步静态源、启用 API 源等外部动作不能隐含在读接口里。

## 12. 安全、运行与可观测性

管理登录、管理 API 和下游 API 明确隔离。管理密码使用合适的密码哈希，随机 API Key 用不可逆校验值；代理和供应商凭证需要可逆加密时，密钥不与数据库一起保存。日志、备份、网页和错误响应都视为可能泄漏面。

反代部署按可信 CIDR/跳数判断转发头；只在可信链路中接受 CF-Connecting-IP/X-Forwarded-For，不能对任意直连客户端直接信任。线上管理 Cookie 强制 Secure、HttpOnly、SameSite，敏感 API 禁止缓存，并补齐 CSRF/Origin 校验。登录和公开 Judge 限流表必须有有界容量及过期清理。

所有配置进行范围和关系检查：并发/分页不得为非法零或负数；时间换算先检查上限再乘法；请求截止要给写响应留余量。共享容量以槽位或预约自己的 fence 管理，不能每次预约互相作废。失败证据、健康和熔断使用统一时序规则，旧成功不能清除新失败。

服务退出时先停止入场和新后台派发，取消/收敛工作，再关闭数据库；后台任务不再使用无法跟随服务关闭的裸 `context.Background()`。恢复时把未完任务标为中断或按安全游标继续，不重复购买，不永久占用许可。

至少记录以下指标：

- 请求成功率、完整交付率、部分交付率、交付条目数、各阶段延迟和缺口原因。
- 每源调用量、空/重复/CD 排除率、验活通过率、抓取与质量熔断次数、换源次数。
- 粘性命中、同出口恢复、严格保持失败、允许的出口变更；轮换出口去重率、窗口耗尽和显式降级。
- 静态候选数、近期证据合格数、当前可尝试数，三者不能混称“活跃”。
- 任务 ready_now、排队和执行时间、停止原因；在线和后台槽位占用。
- SQLite 等待和事务耗时、磁盘/WAL、进程 RSS、Go 堆、文件描述符和公网出方向流量。

“今日代理去重通过率”“探测尝试通过率”“下游请求完整交付率”是三个不同指标。验活基础设施异常单独计数，分母要明确。一次探测只归因实际选择的源，而不是因为资源同时属于多个源就给所有源记同一份供应成功。

中间件、编排器、供应商调用、验证和交付共用一个请求追踪 ID。请求 ID、代理 ID 放详细日志，不作为无界指标标签；敏感连接和 Token 永不记录。

## 13. 实施里程碑与退出条件

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| M0 契约冻结 | 确认 API 不入池、sticky/rotate、会话复用与新分配 CD、预热 ready 定义、类型与权限 | 形成可执行验收用例；旧文档冲突标记清楚 |
| M1 正确性修复 | 租约归属、批量队列停止、健康结果、资格检查、DNS 拨号策略、地区过滤、预算和时间边界 | 本次复现场景变为正式回归测试并通过；不改变现有秘密配置 |
| M2 模型与管理 API | 渠道/适配器分离、配置编辑、消费者、业务路由、会话绑定、统一任务骨架、兼容接口 | 配置真实可编辑；导入不覆盖配置；会话权限与版本明确；迁移可演练 |
| M3 双供给管线 | 静态 URL 同步；API 临时候选及已交付会话私有快照；租约与静态库存解耦 | API 取号/粘性命中库存零增长；URL 失败不清池；未用或终态 API 条目不回池 |
| M4 调度与任务 | 粘性保持/同出口恢复、轮换去重、及时换源、双维熔断、半开、在线优先、预热、原子交付/CD | 严格模式不暗换出口，轮换不暗复用；坏源及时切换；预热与并发/重启语义正确 |
| M5 管理页交付 | 渠道、静态库存、任务、应用密钥、业务路由/活动会话、调用记录、设置 | 桌面/手机流程验收，模式/连续性清楚，无静默失败或 API 入池文案 |
| M6 发布与运行 | CI 门禁、固定 SHA 构建、版本接口、备份恢复、迁移及回滚演练、目标机测量 | 测试/构建 SHA/运行 SHA 可核对，配置不漂移，资源与故障测试达标后才部署 |

按可验证的小提交和里程碑交付，不一次性重写所有代码。管理页布局可以先做线框与接口约定，但最终按钮必须绑定已经实现的业务语义。安全缺陷不必等整套新 UI 做完才修复。

### 13.1 迁移特别注意

1. 先获取一致备份：使用 SQLite backup API 或停止写入后的离线备份；不能在活动 WAL 模式下只复制主 `.db` 文件。
2. 先在备份副本上演练 schema 升级、数据映射和恢复。迁移报告列出静态资源、API 历史供给、活动租约和 CD 数量。
3. 把现有 custom 映射为静态上传，provider_api 映射为 API 按需。旧 API offer 从可选库存退出；共享静态资源不能误删。
4. 活动 API 租约先排空，或迁移为非库存交付记录；指纹和仍有效的消费者窗口保留，不能通过迁移清空 CD。
5. 每个现有 Key 建立对应消费者，保留默认 CD；随后轮换仍绑定同一消费者。管理密码、master Token、身份密钥原样保持。
   现有租约没有业务会话键，不能按整把 Key 猜测为一个粘性账号；旧调用保持无会话的兼容入口，新业务显式配置路由和 mode。
6. 整数时间迁移需校验旧数据解析并重建相关索引；禁止直接改列含义后让旧二进制继续写入。
7. 发布镜像按不可变 SHA/digest，记录 schema 版本和配置版本；单机只允许一个活动应用进程，不用两个容器共同写同一 SQLite 来做灰度。
8. 回滚必须考虑新交付和新 CD，不能随意恢复旧库丢失窗口；优先兼容迁移或向前修复，必要的恢复需停写并对交付状态进行核对。

### 13.2 CI 与上线检查

CI 先跑 go vet、完整测试、竞态测试、前端语法/组件检查，再允许构建推送镜像。浏览器流程测试覆盖渠道编辑、任务状态、密钥权限及移动端。

发布前检查安全配置、网络可达性、磁盘容量和一致备份；发布后核对版本、数据库就绪、管理登录、静态订阅同步、受控静态/API 取号、CD 和跨 Key 拒绝。健康接口区分进程存活和数据库就绪，不能仅返回固定 ok 就证明服务可交付。

真实供应商验收使用明确的小批量和预算；本轮未重新获取到 SCDN 最新文档，文档请求出现连接重置，因此不能把当前 fixture 当作供应商当前线上合同的替代。部署授权和实际部署属于后续实施动作，不由本规划自动触发。

## 14. 最终验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 同 ID 再创建、两个管理员同时编辑 | 创建冲突；旧配置版本不能覆盖新版本 |
| 给既有源追加上传 | 只导入数据，不重置类型、启停、保留期和并发 |
| URL 初次同步、重复同步、304、超时、403/429、截断、超大正文 | 正确统计；频控退避；失败不清池、不记代理死亡 |
| URL/代理域名指向私网，或重定向/DNS 变化到私网 | 实际连接被网络策略阻止，不只做表单校验 |
| API 按需取号成功、失败、重复和多返回条目 | 请求内使用；库存零增长；未用条目不变成后续候选 |
| 源 A 还有大量库存，但连续候选失效，源 B 可用 | 本次请求在预算内切到 B，不把剩余预算耗在 A |
| 熔断刚到期，多个取号请求并发 | 每源只有一个恢复试探；失败退避，旧结果不能解熔断 |
| 16 个可用候选，请求 2 条 | 达标后结束调度，不因无人消费的队列等到超时 |
| 尝试上限 1、候选页 8 | 实际探测最多 1 次，不按页超发 |
| 已选候选后停用源、代理进入冷却、源配置更新 | 后续预约/提交/最终交付不能使用失效资格 |
| 容量 1 与容量 2 的并发请求 | 不超配；容量 2 不因资源级 fence 相互作废 |
| 代理失败后重新成功 | 正确保存 FAIL/PASS，成功按时序刷新健康并清除旧连续失败 |
| 国家过滤冷启动、出口国家变化、GeoIP 不可用 | 未观察候选可验证；返回项满足本次观察，不静默忽略国家要求 |
| A 应用 cd=300，之后以新会话/rotate 请求 cd=0，B 同时请求 | A 新分配不能缩短旧窗口；B 独立；原有效粘性绑定可复用自己的分配 |
| CD 临界时间、重启、数据库写入故障、部分批次失败 | 时间精确；窗口持久；必要落库失败不交付；失败未发送批次不误记交付 |
| A 取得租约，B 释放/反馈；同一反馈多次提交 | B 被拒绝；重复反馈不重复扣健康，业务站点拒绝不直接判代理死 |
| 库存已有 80 条近期合格，预热目标 100 | 主要补齐缺口；完成时重新核算，不用本轮累计 PASS 冒充 ready_now |
| 预热期间资源过期、被租用、国家不符、达到截止 | 就绪数反映资格变化；不足原因可见，API 候选不计入 |
| 夜间验活/预热和取号同时发生 | 在线请求优先；无重复探测争抢；后台槽位/队列有硬界限 |
| 任务取消、进程中断、恢复 | 可查到终态或恢复状态，许可回收，不重复外部副作用 |
| 管理页面移动端、网络失败和会话过期 | 布局可用、错误明确、无过期数据伪装成功、敏感值不留存 |
| 单机持续负载、历史清理、迁移和回滚 | 测得 RSS/数据库等待/磁盘增长；租约和 CD 不丢，不靠 Redis 掩盖正确性问题 |
| 同会话连续/并发取号、服务重启 | 一个生效绑定，命中不重复取供应商、不增加容量；每次取号仍验活 |
| 原粘性节点失效，有/无相同出口候选 | 合格同出口替代不延长 TTL；严格模式无候选明确失败，不暗换出口 |
| 明确允许重绑、会话过期、慢旧操作返回 | 连续性变化可见，generation 防覆盖，到期不被当成从未创建 |
| API 来源粘性会话创建、命中、释放 | 仅私有绑定保留连接，库存不增加，终态不回池 |
| 爬虫窗口内多个端点同出口、并发同出口 | 按出口原子去重，不用不同端口冒充新 IP，耗尽明确返回 |
| 连续必换配置下 cd=0、仅剩一个出口 | 仍执行上次出口排除，无新出口报耗尽，而不是随机复用 |

## 15. 建议确认的默认决策

为避免无限讨论，建议以这些默认值进入下一轮实施：

1. 静态默认追加同步，手动同步为默认；需要周期时显式开启。破坏性的快照替换后置。
2. 内置适配器可配置渠道实例，但不在线编辑代码；第一批只实现真实需要的 SCDN 和静态 URL。
3. 新分配默认静态优先、API 兜底，源优先级可改；粘性先查绑定，API 不建立可复用库存。
4. CD 属于稳定下游应用，限制新分配；自己的有效粘性绑定允许复用，旧窗口不可缩短。爬虫模板支持出口 IP 去重及连续排除规则。
5. 预热只针对静态库存、保留正式取号时重新验活；下游预热是单独授权能力。
6. 沿用单进程 Go + SQLite；修好事务、状态和任务边界后再评估性能，现阶段不引入 Redis。
7. 保留自建签名 Judge + 本地 GeoIP 作为可用基线，提供受控第三方 HTTPS 探测扩展；不为了流量使用不符合条款或可伪造的响应。
8. 不自动改变任何现有密码或 Token，不把规划文档等同于已推送或已部署。
9. API 业务模板使用 sticky，爬虫模板使用 rotate；来源与模式独立。严格粘性不能保留出口就报错，显式允许重绑时才可换出口。
10. 保留取号服务边界；如以后需要固定入口透明轮换，单独评估转发网关及其业务流量成本，不因参考 Resin 就默认引入。

其中第 4 项改变当前 `cd=0` 的实际语义，应在实施前明确确认；其余多数是既有需求的落地或对错误实现的修正。
