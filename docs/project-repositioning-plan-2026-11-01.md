## 1. 项目定位

**这是一个面向下游业务的、多渠道、按数量供给、经过验活的代理获取服务，不是替下游转发业务流量的代理网关。**

首要下游是“暗盘研究”：需要抓取 5000 多只个股的五分钟 K 线等数据。股票数不直接等于代理数，也不直接等于请求频率；实际需求量、成功率和吞吐上限留待真实业务测试。

新增下游场景是用户准备编写的注册机：代理池向它提供代理连接及验活信息，它作为独立项目使用项目 Key 取号。外部程序向池推送代理是导入操作；注册机若同时需要导入，应另行授予上传权限，不能用取号权限修改库存。

服务负责找代理、验证、筛选、发放和维护供给。下游自行连接代理、访问目标接口、处理反爬与业务重试。股票响应正文不经过本服务。

### 1.1 成功标准

- 下游只提供身份密钥和数量就能使用，其余条件都有默认行为。
- 尽早交付满足条件的代理；数量达标立即结束，超时返回已经取得的部分。
- 库存存在但质量差时能及时切源，不让下游一直撞死代理。
- 项目级 CD 跨进程、跨密钥、跨来源成立，不能被缓存或竞态绕过。
- 管理员能区分供给、库存、验活、发放、任务和云流量状态，知道不足的原因。
- 失败归因准确，不把目标拒绝、渠道凭证问题或本服务超时都算成代理死亡。

### 1.2 本轮不做

- 不建设统一业务转发入口，不代理下游真实抓取请求。
- 不实现股票接口、Cookie、验证码、登录或站点反爬适配。
- 不承诺任意免费代理对业务必然成功，不承诺下游网络与验活服务器网络一致。
- 不强制按实际出口 IP 排重；额外的出口级策略由下游决定。
- 不默认维持无限活跃库存，不自动购买代理或付费额度。
- 不因参考 Resin 就引入其整套网关、路由或强制固定出口机制。
- 不为旧取号 API 建兼容层；但现有数据、配置和凭证必须保留或明确迁移。
- 不把新增需求直接混进已确认范围，后续新增再讨论。

| R30 | 程序导入支持逐行文本和结构化 JSON 批次、按来源授权的上传 Key、批次幂等及结果查询；导入成功不等于验活成功。 |

| R32 | 注册机作为独立下游项目接入；多步流程可使用可选粘性，换绑必须可识别，连接绑定不承诺出口 IP 永远不变。 |

## 3. 明确覆盖旧方案的地方

| 旧文档或旧行为 | 本轮规则 |
| --- | --- |
| 静态优先，库存耗尽才调用 API | API 是默认供给偏好，结合质量与时间预算动态选择，不死等某一类来源 |
| 每次返回都必须重新验活 | 本地近期合格结果允许复用；不能复用不匹配或失效的证据 |
| 爬虫强制出口 IP 去重 | 只保证连接级 CD，出口级额外判断留给下游 |
| CD 按 Key、按本次参数回看历史 | CD 按稳定项目身份、按已写入的到期时间执行 |
| 明确失效后留下 tombstone 防止重新导入 | 直接删除明确失效连接；不保留这种黑名单 |
| 连续超时达到次数就等于已证明死亡 | 状态不明仍保留；次数主要控制退避，不能替代失败归因 |
| 粘性默认要求同出口，否则报错 | 默认不启用粘性；启用后有效复用，明确失效或到期自动换新 |
| 供应商按需 API 不入池意味着完全没有持久记录 | CD、必要交付元数据及会话私有绑定可持久化，但不可成为公共候选 |
| 把外部 API 推送归入供应商按需取号 | API 推送与文件上传等价，进入同一个持久代理池 |
| 月流量阈值触发自动停服或停后台 | 只告警，不自动改变取号和验活运行策略 |
| 几个来源解析出 IP 就算全渠道验收 | 每个渠道分别记录抓取、解析、代理实测和限制条件，失败不能算通过 |

## 4. 对象与职责

### 4.1 适配器与渠道实例

适配器是代码能力，负责构造请求、认证、解析、分页、返回协议、有效期及错误归因。注册信息包括适配器 ID、版本、配置字段定义和能力声明。

渠道实例是一份实际配置，拥有独立的名称、凭证引用、启停、配置版本、调度偏好、调用限制和统计。一个适配器可以有多个实例。

后台“新增渠道”是选择已经实现的适配器并填写配置，不是在线编写 API 适配代码。普通静态 URL 可复用已支持格式的通用下载与解析适配器。

如果供应商按账号、服务器出口 IP 或平台总量限流，多个实例还需共享相应限流约束，不能假定不同 Key 就必然拥有独立额度。

### 4.2 三类供给的存储边界

| 类型 | 保存内容 | 获取方式 | 后台维护 |
| --- | --- | --- | --- |
| 本地导入（文件上传 / API 推送） | 同一个持久池中的候选、来源关系、健康和观察信息 | 两个等价入口，经同一导入流程追加合并 | 同一套定期验活、手动验活、预热及发放规则 |
| 静态 URL 列表 | 有容量及 TTL 的候选缓存、下载元数据 | 池主动下载，允许显式配置周期刷新 | 缓存过期刷新、条件请求、明确操作记录 |
| 供应商按需取号 API | 当前请求的临时候选 | 下游需要新分配时由池主动调用供应商 | 配置测试和小批诊断，不做公共库存预热 |

文件上传和 API 推送可以使用同一渠道，也可以用不同 `source_id` 记录来源、权限与统计。入口类型不参与连接身份或 CD，不建立“文件池”和“推送池”。同一连接跨入口、跨渠道导入时，共用连接级去重和健康维护，并保留各自来源关系；项目仍只能使用获准渠道提供的连接。

API 推送的方向是“外部程序向池提交代理”；供应商按需取号的方向是“池向供应商申请代理”。本文件中“不入池”的规则只针对后者。静态 URL 沿用已有短期缓存设计；缓存 TTL 表示下载结果何时需要刷新，不代表列表中的代理必然在该时刻失效，也不会用于清除文件或 API 推送导入的持久库存。

不能仅因 URL 含有 `api` 就认定为实时按需取号。有些 JSON/TXT 接口只是静态列表的另一种包装，需要按实际刷新、分配及有效期语义分类。

按需 API 未使用的候选在请求结束后丢弃。普通交付只保留必要指纹和记录，不留可被其他请求重新挑选的连接库存。粘性首次交付建立的连接可在会话私有状态中加密保存，供该会话复用；不会进入公共候选选择器，也不参加库存扫描。

### 4.3 下游项目、密钥和连接身份

- 项目是认证后的业务主体；一项目多 Key，删除或轮换 Key 不删除项目 CD。
- 项目身份从认证结果确定，不信任请求体里伪造的项目 ID。
- 连接指纹由真实连接参数生成：协议、规范化地址、端口、凭证版本，以及真正影响上游连接的会话凭证等。
- 项目 ID、来源 ID 和下游自定义 session_id 不参与连接指纹，否则换这些标识就能绕过 CD。
- 相同连接跨来源统一识别；相同出口 IP 的不同连接不自动合并。
- 凭证更新意味着连接配置变化，不能因为旧凭证失败就永久拉黑整个 IP。

## 5. 总体架构

继续采用单体 Go 服务，不拆微服务，不引入独立消息队列或 Redis。

```text
Downstream API -> Authentication / Project Defaults
                       |
                 Acquire Coordinator
                  /          \
        Sticky Binding     Source Scheduler
                              |
                Provider Adapters / Static Cache / Imported Inventory
                              |
                  Validation + Evidence Cache
                              |
               Atomic Delivery + Project CD + Binding Update
                              |
                         JSON Response

Admin API -> Source / Project / Inventory / Job / Settings Management

File Upload / API Push -> Shared Ingestion -> Same Persistent Inventory

Background Jobs -> Prewarm / Periodic Validation / Static Refresh
                       |
                  Shared Bounded Workers

Daily Usage Job -> Huawei Read-only Adapter -> Usage Snapshot -> Bark Outbox

Durable State: SQLite        Disposable State: Bounded TTL Caches
```

网络调用在数据库事务外执行。短事务只做领取资格、版本检查、发放提交、CD 和绑定更新。关键持久化失败时不能继续返回代理。

数据库使用 WAL、合理的忙等待和受控连接数；具体数值需要在目标服务器验证。内部预约用于防止并发重复发放，不声称能控制下游已经拿走的代理地址或实际连接数，也不要求业务每次使用完必须调用 release。

## 6. 下游取号与输出契约

本节为 2026-11-02 讨论后的目标契约。当前工作区已有取号接口与基础 JSON 响应，新增字段及序列化调整尚需实施；第 6.5 节列出本次核对的差距。文档示例不代表所有字段已经上线。

### 6.1 请求

使用 `POST /api/v1/proxies/acquire`，通过 `Authorization: Bearer <project-key>` 认证。请求与标准响应均为 `application/json`。

最简请求：

```json
{
  "count": 10
}
```

带可选条件：

```json
{
  "count": 10,
  "timeout": 30,
  "cd": 600,
  "country": ["CN"],
  "protocols": ["http", "socks5"],
  "validation": {
    "mode": "tls",
    "target": "api.example.com:443"
  }
}
```

| 字段 | 未传时 | 约束 |
| --- | --- | --- |
| count | 建议为 1 | 正整数，受服务端单次上限约束；超限明确报错，不静默改成另一个数量 |
| timeout | 项目或全局默认，建议 30 秒 | 秒；覆盖排队、拉取、验活、切源和提交的整个请求预算 |
| cd | 项目默认 CD | 非负秒数；0 只表示本次新发放不建立额外窗口，不能清除旧窗口 |
| country | 不限 | ISO 国家代码；不允许用不匹配或未知国家凑数 |
| protocols | 使用服务支持的默认集合 | 首版为 http / socks5；对应响应的 connection.transport，未知或未支持的协议明确报错 |
| source_ids | 自动调度项目获准使用的渠道 | 显式指定时只使用该范围，不能偷偷越界兜底 |
| validation | 预设基础验活及默认目标 | 目标 TLS 模式需有目标地址；缺字段时按明确默认规则处理，不静默降低验证强度 |
| mode | ordinary | sticky 为显式可选项 |
| session_id | 普通模式不需要 | sticky 时必填，在项目内识别；建议首版一个会话绑定一个代理，因此 sticky 的 count 为 1 |

请求覆盖项目默认，项目默认覆盖全局默认；所有请求仍受服务端安全上限、权限和已有 CD 约束。“未传”与“明确传 0”必须能区分。

国家或验活模式等条件不满足时返回不足，不为凑数量悄悄换国家、跳过目标检测或关闭 CD。

### 6.2 响应

不足是正常业务结果，不要求额外传 `allow_partial=true`。建议成功处理的请求统一返回 HTTP 200，含已取得结果和缺口；零条也用可解释的空结果表示供给不足。身份错误、非法参数、服务容量不足、存储故障等另用明确的 4xx/5xx。

`delivered` 等于 `items` 长度，`missing = requested - delivered`。`partial` 只在 `0 < delivered < requested` 时为 true；零条返回 `items: []` 和缺口原因。缺口字段统一为 `reason`，不足时必返，足量时省略；正式契约不再同时定义 `shortfall_reason` 别名。

| --- | --- |
| lease_id / source_id | 本次交付标识与来源渠道；来自文件或 API 推送的结果采用同一结构 |
| connection.transport / host / port | 真实代理连接协议、地址和整数端口；host 可为 IPv4、IPv6 或域名 |
| connection.username / password | 所需的实际代理凭证，使用原始字符串；无认证时省略，不返回管理或供应商取号 API 密钥 |
| proxy_uri | 由 connection 生成的便捷表示，认证信息正确编码，IPv6 地址使用方括号；connection 是标准数据来源 |
| observed | 有实际证据时返回 exit_ip、country_code、observed_at 等；未知观察省略，供应商标签不能冒充实测结果 |
| validation | 检测模式、TLS 模式的 target、completed_at、latency_ms、cache_hit，以及证据复用截止 valid_until；与真实检测范围一致 |
| lease_expires_at | 本服务交付租约期限，不代表代理自身到期或可用性保证 |
| provider_expires_at | 供应商声明的代理到期时间；未知为 null，不用缓存 TTL 或租约期限代填 |

粘性响应在顶层另外返回 `session_id`、`binding_version`、`session_changed`、`binding_expires_at`，发生换绑时附 `change_reason`。普通模式省略这些会话字段。`session_changed` 为明确布尔值，不能让下游依赖缺字段猜测是否换绑。

租约、供应商代理、验活证据和逻辑绑定的期限分别表示，时间统一为 UTC RFC 3339，延迟单位为毫秒。证据在 valid_until 前仍可能因新失败或配置变化失效，不能把任一时间字段包装成“代理保证可用至某时刻”。

请求缺口原因区分无候选、CD 排除、国家不匹配、渠道冷却、验活未通过、预算结束等；混合失败可给出脱敏计数摘要。注册机等下游按结构化字段接入，不从代理字符串反推来源、认证或健康状态。

### 6.4 协议、认证与客户端表示

| transport | 首版范围与语义 |
| --- | --- |
| http | 连接 HTTP 代理；通过 CONNECT 可以访问 HTTPS 目标，目标 TLS 验活仍独立记录 |
| socks5 | 连接 SOCKS5 代理，携带所需的用户名与密码；客户端接入说明需明确目标 DNS 在本地还是代理端解析 |
| https | 表示到代理本身建立 TLS，当前未实现；不能把供应商“支持 HTTPS 目标”的标签直接映射为此值 |
| 其他协议 | SOCKS4 或其他节点协议在连接、认证和验活能力实现之前不开放；未知值明确拒绝 |

输出协议字段统一为 `connection.transport`；旧规划中的 `connection.protocol` 不作为另一个字段保留。协议与目标能力分别表述，HTTP CONNECT 通过不代表所有目标、普通 HTTP 转发或其他传输能力均已验证。

`connection` 中凭证保持原始字符串，生成 `proxy_uri` 时才进行 URI 编码，避免双重转义；空密码与无认证按实际认证配置区分。SOCKS5 的 DNS 选择及客户端使用 `socks5` / `socks5h` 的约定需通过对应客户端验证，不能仅修改 URI scheme 就声称支持不同的 DNS 行为。

真实凭证只返回给获准取得该连接的下游，响应通过 HTTPS 交付并禁止共享缓存；日志和管理列表继续脱敏。`proxy_uri` 是 JSON 中的便捷字段，首版以完整 JSON 作为标准交付格式。

注册机使用独立项目 Key，按需传 `mode: "sticky"` 与 `session_id`。出现 `session_changed` 时，由注册机决定继续还是重开业务流程；连接绑定不能替代对供应商出口稳定能力的确认。

## 7. 动态调度

### 7.1 调度前先做资格过滤

先排除未授权、停用、明确凭证失效、调用频控未到、已熔断、协议不符或供应商已明确到期的来源与候选。项目 CD 尽量在验活前过滤，提交时再次检查。

国家提示可用于排序和向上游传参，但不能仅靠不可信标签把候选判成国家已验证。没有历史国家的候选不能永远失去被探测的机会。

### 7.2 API 优先是偏好，不是僵硬串行顺序

综合项目偏好、渠道优先级、近期同口径成功率、响应时延、剩余额度或限流时间、重复率和本次时间余量选择下一批来源。首版用可解释的规则及滑动统计即可，不需要机器学习调度器。

调度流程：

1. 解析默认值、建立整次请求截止时间，并检查是否为有效粘性绑定命中。
2. 计算缺口，从符合条件的来源中选择下一次供给操作，默认偏好实时 API。
3. 按缺口和近期验活通过率估计有界候选量，受适配器批量上限、并发、频率和尝试数约束。
4. 对当前候选先做连接去重、CD 和明确到期检查。
5. 可合法复用近期结果的本地候选走缓存检查；其他候选进入有界验活。
6. 只把满足所有条件的候选计入准备交付数量。
7. 当前来源连续没有有效贡献时提前切源，即使它还有大量未测库存，也不能占满整次请求。
8. 一轮 API 候选失败后，允许在剩余预算内继续其他批次或渠道；不保留当前“一次有候选就不再找别的源”的限制。
9. 凑够立即停止新增拉取和检测，取消无必要的在途工作；允许少量已经开始的有界 I/O 收尾，但不得继续无限取号。
10. 为最终提交和响应留出预算，交付可用部分；不能因最后一个慢探测超时就丢掉之前已经取得的全部结果。

多个来源可以合并贡献同一次响应。来源偏好不能越过显式 source_ids、国家、验活要求或 CD。

### 7.3 区分来源的几种状态

- 获取健康：上游 API 是否可调用、认证是否有效、响应是否可解析。
- 供应质量：取回的代理在特定验活范围内是否可用；目标失败不能无条件污染全局质量。
- 频控与额度：最小调用间隔、Retry-After、免费额度恢复时间。
- 运行熔断：CLOSED、OPEN、HALF_OPEN；半开时只允许一个受控试探。
- 项目排除：因为某项目 CD 耗尽候选，不代表渠道本身失败，不能错误熔断供给方。

授权失败进入需修复状态，不无限自动重试。限流按真实限制范围处理；临时失败用有上限、带抖动的退避。恢复后逐步重新参与调度，避免全部请求同时打向刚恢复的渠道。

### 7.4 缓存与并发

静态列表按渠道实例与配置版本缓存，设 TTL、条目数和字节数上限，支持 ETag/Last-Modified。并发请求可合并同一静态列表刷新，避免重复下载。

按需 API 的批次仍归发起请求，不把取号的 singleflight 结果偷偷变成跨请求公共候选池。可以统一限速和分配调用许可，但未使用代理不得成为另一请求的库存。

在线取号优先于后台巡检和预热；后台仍获得有限公平份额。所有工作有独立的短超时与取消检查，不能创建无限量等待 goroutine。完整请求预算包含排队。

## 8. 项目级 CD 与原子交付

### 8.1 固定到期时间

新发放成功提交时写入：

```text
key = (project_id, connection_fingerprint)
blocked_until = issued_at + effective_cd
```

检查依据是已存在的 blocked_until，而不是“用这次 cd 往前看多久”。后续调小参数、传 0、换 Key、换源、重启服务或重复上传，都不能缩短旧窗口。

CD 为 0 时，新交付不额外建立冷却窗口，但已有未到期记录仍然生效；因此不能把 cd=0 描述为必换代理或必换 IP。单次结果内部仍按连接去重。

### 8.2 两阶段处理

1. 短事务领取候选发放预约，防止同项目并发请求同时处理同一受保护连接。
2. 在事务外验活或检查可复用证据。
3. 提交事务复查权限、源版本、候选状态、证据有效性、CD 和预约所有权。
4. 将实际选入响应的交付、对应 CD，以及需要的会话变更一并提交。
5. 只有提交成功才返回；没有入选响应的多余候选释放预约，不消耗该项目 CD。

CD、预约和会话表不能依赖“公共库存必须存在”的外键，否则供应商按需候选不入池和明确失效删除会破坏一致性。删除库存不级联解除 CD；删除 Key 不级联删除项目记录。

进程重启后恢复未到期 CD，清理或接管已失效的短预约。慢的旧任务通过 token、配置版本和对象 incarnation 检查，不能覆盖新状态，也不能在删除后重新 upsert 复活旧对象。

发放在工程上以“持久化提交并准备发送”为边界。响应途中断网时无法证明客户端有没有收到，因此不回滚已经提交的 CD；不承诺无客户端回执的网络交付恰好一次。

## 9. 验活、观察与失败归因

### 9.1 默认基础验活

下游不传验活配置时，使用管理员预设的基础方式和检测地址。保留现有小响应、可校验的 IP 回显探测作为实现基线；检测端点可来自自建 Judge 或明确实现的受信第三方适配器，不要求永远回打本服务器。

自建 HTTP Judge 必须保留正确的 nonce/签名验证；HTTPS 目标需要正确的证书验证。第三方接口需核查条款、限流、响应可信性和失败切换，不能为了少一点流量接受可伪造的任意回包。

ip-api 一类服务按调用出口计数时，不是整套代理服务共享一个固定次数限额；但共享出口、重复探测仍可能触发限制。应按官方规则和实际响应处理，既不把它误算成全局 45 次，也不假定完全没有限制。

### 9.2 可选目标 TLS 验活

```text
Server -> Candidate Proxy -> Target Host:Port -> TLS Handshake / Certificate Verify
```

通过代理协议完成认证与隧道，再以目标域名作为 SNI 和证书主机名完成 TLS 握手。成功后关闭，不发送目标业务 HTTP 请求、不读取网页正文。

仅代理 TCP 端口可连接不算通过；代理声称 CONNECT 成功但无法完成目标 TLS 也不算通过。不能关闭证书校验、绕过代理直连后冒充结果，或把无法支持 TLS 隧道的代理按弱检测当成成功。

TLS 模式验证的是域名与端口，不是 URL 的业务路径。若以后需要 HTTP 状态或内容验证，应另行明确需求，首版不增加任意业务请求脚本功能。

该结果不保证后续 HTTP 不返回 403、429 或验证码，也不保证下游网络能连到同一代理，更不是“未被 GFW”的全局检测结论。

### 9.3 国家与出口信息

TLS 握手本身不返回实际出口 IP。需要国家筛选时，使用合格的出口观察，必要时增加一次轻量 IP 回显，再通过离线 GeoIP 数据库查地区；不能用代理入口 IP 的国家冒充出口国家。

国家观察必须携带来源和时间。不可信供应商标签可用于候选排序，不直接作为最终已验证证据。不同连接可能采用不同出口的轮换网关，只能给出观察时结果，不能承诺下游下一次连接仍然相同。无法满足所请求的证据条件时返回不足，不编造匹配结果。

没有请求国家时，不为去重强制额外获取出口 IP；默认基础探测本身带来的观察可以正常返回。

### 9.4 近期结果复用

缓存至少按真实连接上下文、凭证版本、验活方式及版本、目标域名端口和安全配置区分。基本 IP 回显的成功不能替代指定业务域名 TLS 成功，目标 A 的通过不能冒充目标 B 通过。

本地候选在短期有效窗口内可以跨合格下游复用证据；各项目仍要有来源权限并各自检查 CD。近期有新的负面证据、凭证变化、源配置失效或对象删除时，旧 PASS 不继续生效。

按需 API 新取出的候选默认做本次验活；不能依赖历史记录跳过本轮验证并形成隐形库存。已建立的会话私有绑定可在满足相同条件的短窗口内复用结果，否则重新验活。

### 9.5 失败分类

| 失败事实 | 归因范围 | 处理 |
| --- | --- | --- |
| 正确提交代理凭证后被明确拒绝 | 这份代理连接配置 | 直接删除本地连接或丢弃临时候选，失效绑定不再返回 |
| 供应商明确撤销或到期 | 对应供给授权或连接 | 移除该无效供给；连接没有其他有效供给时删除，不误删别处仍有效的授权 |
| 取号 API Key 无效、账号授权失败 | 渠道实例 | 暂停拉取并提示修复，不能把既有代理全部删除 |
| 调用限流、免费额度耗尽 | 对应限流作用域 | 等待允许恢复的时间，不判代理死亡 |
| 超时、连接重置等不能确认永久失效的情况 | 连接或目标的暂时不确定状态 | 保留候选与必要原因，退避后复测，不仅凭次数永久删除 |
| 目标 TLS/目标站点异常 | 相应目标验证范围 | 本次不满足目标条件；不直接推导代理全局死亡 |
| 默认检测服务异常、签名配置错误等基础设施问题 | 检测设施 | 暂停错误归因、展示诊断，避免批量误删 |
| 整次请求预算耗尽、排队取消或客户端断开 | 请求 | 停止工作，不把这个事实计为代理故障 |

HTTP 状态码须结合返回层级和适配器语义判断。例如网站 403、供应商 API 403 和代理认证拒绝不是同一个错误。证书异常或回显校验异常要拒绝当前证据，但必须区别目标、代理和本服务配置问题，不能一律全局删除。

### 9.6 删除与不确定状态保留

明确失效时，删除可复用连接内容、相应公共候选、健康缓存和失效会话的旧连接快照。不得维护用于阻止未来导入的失效库、黑名单或 tombstone。

不确定状态才保留可复测候选及原因。来源限流状态、项目 CD 和任务级统计不是失效代理库存，按各自职责和期限保留。

没有失效黑名单就意味着：未来一份旧文件或新拉取批次再次给出同样的坏连接时，可能再次作为未验证候选出现。这是直接删除规则的自然代价，不能暗中用持久黑名单恢复旧行为。可以从当前批次/缓存中移除已确认坏条目，并在当前请求内去重；后续重新出现仍必须验证，不能直接恢复成 PASS。

保留渠道级删除计数、错误类别等统计即可，不为统计重新保留坏代理连接明细。已生效的项目 CD 仍独立保留到期。

## 10. 本地库存维护与预热

### 10.1 文件上传与 API 推送

文件上传和 API 推送是同一个导入能力的两个入口。两者均独立于渠道创建和配置编辑，复用解析、规范化、校验、追加合并及同一个持久代理池。来源渠道可以相同或不同，入口差异不改变连接身份、生命周期、健康维护或发放规则。

已有连接不因本批未出现就被删除。重复或交替使用文件、API 导入同一连接，不重置启停、健康、验活记录或项目 CD；连接跨来源时保留来源关系，按连接去重。本地新候选初始为未验证状态，导入成功不表示可直接发放，也不接受上传方用 PASS 等字段覆盖服务端验活结果。

当前代码已有管理入口：

```text
POST /api/v1/admin/sources/{source_id}/imports
Authorization: Bearer <admin-token>
Content-Type: text/plain
```

它将请求正文交给 `ImportLines`，仅接收 `custom` 渠道的逐行文本，当前正文上限为 8 MiB，返回 `added`、`updated`、`skipped` 和逐条 `rejected`。程序直接提交文本已可复用这一入口；JSON 批次、专用上传 Key、批次幂等与结果查询仍待实施。

目标程序接口为：

| 接口 | 作用 |
| --- | --- |
| POST /api/v1/sources/{source_id}/imports | 使用上传 Key 提交文本或 JSON 批次，复用管理入口的同一导入服务及库存 |
| GET /api/v1/sources/{source_id}/imports/{import_id} | 在上传身份与来源授权范围内查询该批结果 |

文本格式使用 `text/plain`，每行一条 `http://[user:pass@]host:port` 或 `socks5://[user:pass@]host:port`。裸 `host:port` 使用渠道明确配置的默认协议；未知协议拒绝，不能擅自当作 HTTP。文件提交与 API 文本推送使用同一格式。

JSON 格式使用 `application/json`，单条代理也放在 `items` 数组中，连接字段复用第 6 节定义，示例为待实施的目标格式：

```json
{
  "items": [
    {
      "connection": {
        "transport": "http",
        "host": "203.0.113.10",
        "port": 8080,
        "username": "user",
        "password": "p@ss"
      },
      "provider_expires_at": null
    }
  ]
}
```

供应商到期时间已知时可提交 UTC RFC 3339 时间，未知时省略或为 null。JSON 中凭证为原始字符串；文本 URI 中凭证按 URI 规则编码。两种表示规范化后的同一连接必须得到相同身份，后续增加文件格式也复用这条路径。

程序接入同时满足：

- 上传 Key 只授予指定来源的导入和获准批次结果查询权限，不能创建渠道、修改项目或读取管理凭证。项目取号 Key 与上传 Key 分开授权；同一个程序需要两个方向的操作时分别使用对应权限。
- 请求可携带 `Idempotency-Key`，幂等范围绑定上传身份与来源。在公布的保留窗口内，同一幂等键和相同内容返回同一 `import_id` 及结果；同一幂等键不同内容返回 409，不能重新应用为另一批。
- 批次结果具有稳定 `import_id`，报告新增、重复、拒绝计数及有数量上限的逐条错误。正文结构错误拒绝整批；追加批次中的非法条目单独报告，合法条目仍可导入。导入提交与结果记录保持一致，网络重试不能使统计或库存发生第二次变更。
- 连接去重与批次幂等分别实现：换入口重复提交仍保持健康和 CD；重试同一批时可查询原结果。正文、条数、字段长度、错误明细及幂等记录保留期都有明确上限，错误不回显密码。
- 导入完成后候选遵循同一套周期验活、手动验活、预热与请求时验证规则；是否已验活和导入数量分别展示。库存持久化不受静态 URL 下载缓存 TTL 影响。

### 10.2 定期验活

对本地上传库做可配置周期的分页扫描，记录进度，避免全表一次性装入内存。在线请求优先，后台使用受控份额；不能因为有周期任务就无限并发。

周期扫描覆盖应检查的本地候选，不将“检查几个样本”冒充全库维护。不确定状态根据 next_retry_at 安排复测，重复超时可延长退避，但不伪装成明确永久失效。

按需 API 不是周期全量验活对象。静态列表周期刷新与本地上传库验活是不同任务：刷新得到候选，不等于候选已存活。

### 10.3 异步预热

预热接收数量、适用的筛选与验活条件，继承发起项目身份。任务独立于创建它的 HTTP 连接，返回 job_id 后可查询或取消。

Ready 定义为当前仍满足条件的数量：验活证据有效、来源可用、符合筛选、未被该项目 CD 排除。不是本轮累计成功次数，更不是库存总条数。

每轮重新评估 Ready，再补足缺口；达到目标、任务时间结束、尝试额度耗尽、供给无可继续进展或取消时结束，记录最终缺口和原因。不为达标偷偷调用按需 API 囤货。

同一个有效期窗口内能维持的 Ready 数量受探测吞吐约束。后台可以在空闲时借用允许的空闲槽位；若目标数量与当前窗口、质量或并发条件不相容，就如实返回不足，不能把过期证据继续累计为 Ready，也不能为达标偷偷延长证据有效期。

预热不发放、不写项目 CD。推荐首版不增加专属库存预留：完成时达标是一个有时间戳的状态，不保证这些免费代理无限保持存活。正式获取仍检查权限、CD、状态与证据期限。

任务状态持久化为 QUEUED、RUNNING、COMPLETED、PARTIAL、FAILED、CANCELLED、INTERRUPTED 等明确状态。推荐重启后把无法继续保证现场状态的任务标成 INTERRUPTED，允许显式重试；不悄悄把旧累计 Ready 当作当前可用数量。

## 11. 可选粘性会话

### 11.1 身份与首次建立

默认 ordinary，不建立会话。sticky 显式启用，session_id 必填；建议首版 count=1。绑定键为项目 ID 与会话标识的组合，session_id 不是认证凭证。

首次建立绑定是新分配，必须走项目 CD、来源资格、验活和原子交付。并发创建同一会话只允许一个生效版本，不能每个请求都独立消耗一个供应商批次。

### 11.2 命中与 CD 例外

| 操作 | CD 行为 |
| --- | --- |
| 原项目、原会话取回当前绑定 | 可使用该绑定自身的 CD 例外；仍检查授权、源状态、验活和期限 |
| 普通取号、新会话或不存在的绑定 | 正常新分配，不因带 session_id 放行 |
| 原绑定失效后的换新 | 新代理执行正常项目 CD 检查 |
| 释放或到期 | 不取消尚未到期的 CD |

建议命中不重置或延长原 CD，也不无限延长会话 TTL。会话 TTL 是本服务绑定期限，不能包装成供应商对出口稳定或代理寿命的保证。

### 11.3 自动换绑

原绑定明确失效或到期时，按旧代理的失败类别清理；在本次剩余 timeout 内正常获取新代理，成功后原子更新同一个 session_id 的绑定版本，并在响应标记 changed 和原因。

未取得新代理时返回未满足结果，不能继续返回坏代理。并发重绑通过版本和所有者校验控制，慢的旧结果不能覆盖已经更换的新绑定。

本轮粘性是连接绑定及故障自动换新，不是严格出口永不变化。同一代理地址本身也可能轮换出口；当前能力未知的来源不能声称具备供应商级固定 IP 保证。

不额外暗设“粘性绑定永久独占所有下游”的规则；项目 CD 与供应商真实限制分别执行。其他请求不能从会话私有 API 快照里挑候选，哪怕其自己的 CD 尚未使用该连接。

## 13. 华为云流量与 Bark

这是代理服务内置的每日后台任务，不依赖本次聊天持续开启，不另外建立 Codex 定时聊天任务。

### 13.1 管理配置

- Bark 地址、启停、测试推送入口。
- 华为云 Access Key ID / Secret Access Key；建议专用 IAM 身份和最小只读权限。
- 区域、实例或流量包等监控对象，能自动发现的自动发现，再明确确认绑定。
- 总流量、单位、账期、提醒阈值；优先使用云平台的真实计费口径。
- 每日检查时间和时区、重复提醒控制、最近查询与通知结果。

总流量先以用户提供的每月 1024GB 配置为背景，不假定全部都归本进程，也不把操作系统总收发字节直接等同于套餐计费使用量。

### 13.2 执行原则

每日读取云方使用量，保存数据时间、查询时间、已用和剩余。越过阈值通过 Bark 发送简明摘要；同一账期/阈值去重，失败有限重试。查询失败保留上次有效数据并显著标记陈旧或异常，不能写成零用量。

**阈值只用于告警，不进入取号准入、拉取或验活的自动停用逻辑。** 普通的请求预算、并发上限、供应商限流和安全策略仍独立生效。云查询或 Bark 故障也不能卡住取代理热路径。

每日采样可能有接近一天的等待，加上云平台统计延迟，因此不是实时防超额保证。

### 13.3 实施前的外部验证门槛

当前尚未拿到凭证，也没有核实这一具体 Flexus L 套餐能通过哪个官方接口取得可用的流量包使用值。必须先核对：对应产品接口、权限、区域、账期、单位、上/下行计费方向、共享资源范围及数据延迟。

若只能取得监控估算值而非套餐官方使用值，界面和告警必须明确标为估算，不能冒充云账单余量；该替代方案需另行说明后采用。不能在没有依据时断言“华为云都只算上行”。

AK/SK 和 Bark 地址都按敏感配置处理：后台掩码、服务端加密保存、日志与通知不输出秘密。加密主密钥留在受保护的部署配置中，与数据库备份分开保护，不写入仓库。填写凭证不等于授权资源创建、修改、删除或付费。

## 14. 管理台重构

### 14.1 页面分区

| 页面 | 核心内容 |
| --- | --- |
| 概览 | 实时取号表现、来源可用性、本地近期有效候选、任务、异常、云用量与数据时间 |
| 渠道管理 | 渠道实例列表、适配器能力、详情/编辑、启停、配置测试、显式诊断、运行状态 |
| 本地库存与静态缓存 | 分开看持久库存与短期缓存，来源/协议/国家/健康筛选、上传和验活入口 |
| 任务中心 | 导入、下载、预热、周期验活和诊断的任务 ID、进度、取消、结果与历史 |
| 下游项目 | 项目、多 Key、默认 CD/超时/验活配置、允许来源及运行限制 |
| 项目会话 | 可选粘性绑定、期限、版本、换绑情况、显式释放；归属项目可追溯 |
| 流量与告警 | Huawei/Bark 配置、用量与账期、数据新鲜度、提醒记录及失败诊断 |
| 系统与调用记录 | 版本、数据库/缓存状态、默认策略、脱敏调用原因及管理操作记录 |

供应商按需取号渠道不展示虚构的“池内代理数”，它展示调用、返回、验活、发放、时延和限流状态。文件上传与 API 推送的记录展示在同一个本地库存页面，可以按来源和导入批次查询。本地“近期通过数”必须标明默认验活范围和时间口径，不能包装成对所有下游都可立即发放的数量。

### 14.2 交互原则

- 渠道管理以列表和详情为主，不把所有创建表单、统计和任务进度堆在一个页面。
- 创建、编辑、上传、拉取、验活、诊断是不同操作，保存配置不偷偷发起取号。
- 供应商 API 适配器只读展示能力；实例表单只显示该适配器实际支持的参数。
- 静态 URL 有下载与缓存信息，上传渠道有库存维护信息；不提供不会生效的通用字段。
- 配置读取与更新有版本，冲突返回明确提示，避免旧表单覆盖新配置。
- 密钥字段留空默认保持原值；清除凭证需显式操作，不能用脱敏星号覆盖真实密钥。
- 文件与 API 导入显示同一语义的新增、重复、非法条目及批次结果，不把下载/导入数量当作验活数量。
- 默认列表分页，避免一次渲染全部库存；桌面与移动端都能完成核心操作。

视觉上采用清晰的信息层级、统一状态色、稳定表格和详情面板，减少装饰性大卡片。供应商名称、错误和返回内容一律视为不可信文本，不通过拼接 HTML 执行；表单标签、键盘焦点、错误提示及加载状态必须完整。

### 14.3 权限和安全

管理身份和下游项目密钥分离；下游只能获取代理及操作自己获准的任务/会话，不能读取云凭证或修改渠道。管理端处理云密钥时应通过 HTTPS、受控反代与登录保护访问，不擅自更改用户已设定的管理密码或主 Token。

上传 Key 按第 10.1 节限定来源与操作。拥有某个来源的取号权限不自动获得该来源的上传权限，拥有上传权限也不自动获得取号或其他管理权限。

URL 下载、自定义目标和代理地址都要防 SSRF：限制协议和端口策略、私网/回环/链路本地/云元数据地址，处理 IPv6、DNS 重解析及重定向，禁止 URL 自带敏感认证信息。网络响应、解压后体积、分页、文件大小、行数和解析耗时均有上限。

不能在错误日志、URL query、浏览器本地存储或 Bark 消息中泄露管理密钥、云 AK/SK、供应商凭证或完整带密码的代理 URI。

1. 接入文档、免费范围、认证、条款、调用频率、有效期及真实供给类型。
2. 正常、空批次、畸形数据、鉴权失败、限流、网络超时等响应解析与归因。
3. 数量、国家、协议等参数是否真的可用；多页和不同返回结构用 fixture 覆盖。
4. 实际取得的候选是否能完成相应代理验证，记录检测地点、时间、方式、数量和结果。
5. 取消、限流、故障切换、实例启停、凭证更新是否生效。
6. 按需 API 是否始终不进入公共库存，静态候选是否遵守缓存和体积限制。

“每个渠道都检查”不等于宣称每个公共列表中的全部 IP 永久存活。每个渠道都必须实际走到验活环节，并如实披露受预算限制的候选实测数量；不能用渠道抽查代替覆盖，也不能把解析成功率当成代理存活率。

现有 `cmd/sitecheck` 主要以解析出条目判成功，不能单独作为完整验收。建议扩展独立渠道报告，区分获取、解析、真实代理探测、可用数量和失败原因。

参考来源：[SCDN 文档](https://proxy.scdn.io/api_docs.php)、[free-proxy-pool](https://github.com/fog-forest/free-proxy-pool)、[Resin](https://github.com/Resinat/Resin)。复用代码须检查和保留许可证，不直接运行不可信上游脚本。本轮没有重新访问这些服务或消耗供应商配额。

## 17. 建议实施顺序与验收门槛

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| P0 契约与现状整理 | 固化本文件、整理既有未提交改造、记录数据迁移需求和测试基线 | 所有行为与最新规则对应，保留既有工作，不误把旧测试契约当需求 |
| P1 项目/CD/新取号骨架 | 项目与 Key 分离、固定 CD、原子预约交付、部分返回、总超时及第 6 节标准输出 | 多 Key/并发/重启/换源/删除 Key 均不能绕过 CD，超时保留合格部分，连接、认证、期限和缺口字段一致 |
| P2 供给层 | 注册表与多实例、SCDN、已有站点、通用静态 URL、等价文件/API 导入、上传授权与批次结果 | 供应商按需候选不入池，文件/API 推送共用持久池；跨入口去重、JSON、幂等及结果查询可验收，静态 URL 缓存独立，配置可读取修改且有版本 |
| P3 验活与健康 | 默认探测、目标 TLS、国家观察、近期结果复用、分类删除与保留 | 验活范围准确，已确认坏连接删除且无黑名单，未知状态不误删 |
| P4 调度与任务 | API 偏好、多源补足、分层熔断、有限队列、定期验活和异步预热 | 达标早停、有限重试、半开单试探、Ready 为当前有效数量 |
| P5 可选粘性 | 项目会话绑定、CD 例外、原子换绑、私有 API 快照 | 默认关闭，原会话可复用，失效换新不绕过项目 CD |
| P6 管理台 | 按实体和任务重构页面、配置安全、移动端及交互验收 | 不混适配器与实例、不展示虚构 API 库存，关键操作有闭环 |
| P7 云用量与 Bark | 先验证官方接口及权限，再做每日查询、快照与通知 | 数据口径可解释、失败不报零、秘密不外泄、阈值不自动停服 |
| P8 全渠道及发布验收 | 每个渠道报告、回归/竞态/负载/安全测试、备份与迁移演练 | 无假通过，配置和数据保留，部署版本与测试产物一致，可回滚 |

管理台接口与页面可在各阶段增量完成，但不能先做一个看似完整、按钮却不对应真实能力的控制台。云平台接口的验证可提前进行；凭证未提供时不得伪造用量或宣布该阶段完成。

不预先承诺“5000 只股票需要多少个代理”或固定完成日期。先用真实业务测量请求密度、验活通过率、CD 命中、可交付数量、P50/P95/P99 耗时、单位交付字节与服务器资源，再调整运行参数。

## 18. 必须覆盖的回归场景

| 分类 | 验收场景 |
| --- | --- |
| 最小请求 | 只传 count 可运行，其他策略有可追溯默认值 |
| 部分结果 | 要 10 个只找到 6 个，默认返回 6 个；零条也有明确缺口原因 |
| 请求时限 | 传入大于旧 30 秒的合法时间可用；受配置上限保护，不把每个代理时限相加 |
| 早停与取消 | 达标后停止追加工作，取消后不继续取号，不因慢探测丢掉已合格部分 |
| 固定 CD | cd=600 发放后一分钟传 cd=0 仍被排除；原窗口不能缩短 |
| 身份范围 | 同项目多 Key/多进程共享 CD；不同项目独立；客户端不能伪造项目 |
| 跨来源 | 同连接换来源不绕过 CD；不同连接同出口不被强制合并 |
| 持久化与并发 | 存储失败不交付，同项目并发不重复获得处于 CD 的连接，重启不丢 CD |
| 删除与导入 | 上传追加、重复不重置；明确失效删除无 tombstone；再次导入只作为未验证候选 |
| 等价入口 | 同一连接先文件后 API、先 API 后文件，同渠道或跨渠道均共用持久池；不重复创建连接，不重置健康或 CD，保留合法来源关系 |
| 上传授权与格式 | 文本及 JSON 规范化结果一致；取号 Key 不能上传，上传 Key 不能越权写其他来源、读取其他上传身份的批次或调用管理接口；非法条目不冒充可用代理 |
| 批次重试 | 相同幂等键与内容返回同一 import_id/结果；不同内容冲突；超时、并发重试和重启不重复应用已提交批次，结果可在保留窗口内查询 |
| 三类供给 | API 推送成功后进入持久库存并接受周期验活；静态 URL 缓存过期不删除上传库存；供应商按需取号候选仍不入公共池 |
| 旧任务竞态 | 删除、重导入或修改配置后，慢的旧验活不能复活或覆盖新对象 |
| 供应商按需 API 生命周期 | 诊断、普通获取、预热前后该类候选的公共库存始终为零；会话快照不进入选择器 |
| 来源切换 | 库里还有但连续验活失败，也会切源；第一批 API 代理全失败可继续其他来源 |
| 限流与恢复 | 正确处理每实例/共享限制、授权失败和半开许可，不形成并发恢复风暴 |
| 国家条件 | 无观察可冷启动；观察变更后不能用旧国家凑数；未知国家不冒充匹配 |
| 目标 TLS | 仅端口打开、假 CONNECT、错误证书不得通过；成功握手不发送业务 HTTP 请求 |
| 下游协议与认证 | 统一 transport=http/socks5；HTTPS 目标与到代理的 TLS 不混淆；未知协议拒绝；原始凭证、URI 转义、IPv6 与无认证表示正确，DNS 约定有依据 |
| 下游结果字段 | JSON 中 delivered/items/missing 一致；reason 唯一；观察未知不编造；租约、供应商、证据和绑定期限分别表示；凭证只向获准下游交付 |
| 证据范围 | 默认回显不能替代目标 TLS，目标 A 不能代替 B，过期或凭证变更后重新验证 |
| 错误归因 | 代理授权、API 授权、目标异常、Judge 故障、取消和超时各走正确分支 |
| 不确定保留 | 重复临时超时可退避，但不能仅凭累计次数直接认定永久失效并删除 |
| 预热 | 返回 job_id、按项目资格计算 Ready、达标停止、可取消、重启状态明确，不写 CD |
| 粘性默认 | 未开启不建立绑定；开启无 session_id 明确报错，不偷偷变普通取号 |
| 粘性例外 | 只有原项目原会话命中当前绑定可在 CD 内复用；新会话不能伪装命中 |
| 自动换绑 | 原绑定失效/到期取得新代理并标识变化，遵守 CD、期限和并发版本保护；响应显式给出 session_changed，注册机可识别换绑 |
| 多实例渠道 | 同适配器多配置独立启停计量，供应商共享限流仍得到执行 |
| 全渠道 | 每个注册渠道和实际实例均有结果；无凭证或失败不能算通过 |
| 告警 | 每日检查、账期更新、阈值去重、有限重试和查询异常均可测试 |
| 通知不干预服务 | 越过月流量阈值仍正常调度，不自动停止拉取、预热或验活 |
| 安全 | 项目隔离、管理权限、SSRF、DNS/重定向、IPv6、XSS、CSRF、凭证脱敏和响应体上限 |
| 发布 | CI 测试门禁、SQLite 迁移、备份恢复、旧配置/密码/Token 保留和部署版本核对 |

稳定的测试主体使用本地可控代理、供应商 fixture、伪时钟和假云接口，不能把公共免费代理的不稳定性当作单元测试随机失败的理由。公共渠道实测作为独立、带时间与环境说明的报告。

## 19. 试运行参数建议，不是已确认的业务常量

所有参数在管理配置中可见，具体选择应经目标服务器及下游实测修订。初始建议只用于形成可运行基线，不能据此宣称性能或流量足够。

| 参数 | 初始建议 | 说明 |
| --- | --- | --- |
| 普通获取默认 count | 1 | 下游通常显式传数量 |
| 默认 timeout | 30 秒 | 用户认可可配置，30 不是硬上限 |
| 请求时间保护上限 | 120 秒 | 服务配置可改，超限明确报错 |
| 单次 count 保护上限 | 100 | 不保证限时内足量，待压测调整 |
| 新项目默认 CD | 300 秒 | 创建项目时明确展示，可修改；不是从股票周期推导出的结论 |
| 单探测连接/总时限 | 1.5 秒 / 3 秒 | 都受剩余整次请求预算约束，海外质量需实测 |
| 全局验活并发/单请求上限 | 16 / 4 | 有界队列；后台份额受控，需依据 CPU、FD、带宽调整 |
| 本地 PASS 复用窗口 | 30 秒 | 按范围匹配，负面新证据可提前失效 |
| 静态列表缓存 TTL | 5 分钟 | 受来源规则和刷新信息约束，不能当作存活期 |
| 上传库完整巡检周期 | 24 小时 | 配合短期缓存、预热和请求时探测；不是唯一检测入口 |
| 预热默认/保护时限 | 120 秒 / 10 分钟 | 任务本身也有尝试数与并发限制 |
| 逻辑粘性绑定 TTL | 10 分钟 | 不超过已知供应商期限，不代表代理保证可用十分钟 |
| 云流量每日检查时间 | 09:00，Asia/Shanghai | 可配置，与云方账期及数据时间区分 |
| 用量告警阈值 | 已用 80% | 可配置；仅提醒，不自动停服 |

供应商限流参数优先使用其真实规则，不能套用统一数字覆盖官方限制。健康退避、缓存容量和尝试数都必须有边界，但未知状态的保留与月度流量通知不应被这些参数暗改成自动永久删除或自动停服。

## 20. 迁移、发布与后续边界

实施前先整理既有未提交改造，保护其他工作，不重置或覆盖当前修改。历史站点库存按来源识别后迁移到新的持久库存/短期缓存类别，不能把用户上传数据误当缓存清掉。

已有 Key 与项目的对应关系先形成映射清单，不能擅自将不相关业务合并。原身份密钥、管理密码、主 API Token 和凭证默认保留。新 CD 表按可解释规则迁移，不能为了换表把未结束的窗口全清空。

旧表只有 last_delivered_at，未必能还原历史请求实际传入的 cd。能从可靠记录追溯的按原值迁移；无法追溯的不能声称已精确恢复，也不能直接按 0 清空。实施时需先列出受影响记录及建议的保守保留策略，再处理这类迁移不确定性。

测试包含 go vet、完整 Go 测试、race 测试、隔离数据库迁移和服务级验收；不是只构建镜像。发布流程增加测试门禁，镜像以可追溯版本/提交标识交付。

SQLite 备份须使用一致性备份方式或在受控停止写入后备份，不能只复制正在写入的主 db 文件而忽略 WAL。恢复演练同时覆盖数据文件、配置及加密密钥；旧镜像不能直接配新 schema 假装完成回滚。

上线前明确版本、备份、迁移、健康、管理登录、取号/预热/会话验证及观察步骤。提交、推送、部署属于后续实施动作，本次规划不自动触发。

业务规则已经形成这一轮基线。剩余工作主要是技术验证、推荐值调优和实施，不再把每个字段名或代码结构都当成必须由用户逐项决定的问题；新增业务场景另行讨论后更新本规划。
